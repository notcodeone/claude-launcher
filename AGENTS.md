# ClaudeLauncher — правила для агентов

Этот файл читают все агенты: Codex — напрямую, Claude Code — через `CLAUDE.md`, который
импортирует его. Правила одни для всех; меняй их только здесь.

ClaudeLauncher — приложение в строке меню macOS и трее Windows (Flutter 3.44, Dart 3.12),
которое запускает **приложение Claude Desktop** с разными профилями через
`--user-data-dir`. Это личный проект автора для него и команды друзей; репозиторий
публичный — github.com/notcodeone/claude-launcher.

**Только Claude Desktop.** Claude Code в терминале нас не интересует: не делаем для него
функций, команд и алиасов. Claude Code важен только как вкладка Code внутри Desktop.

## С чего начать любую сессию

1. Прочитай [docs/dev/handoff.md](docs/dev/handoff.md) — что сейчас в работе, следующий
   шаг, открытые вопросы. Это состояние, которое оставил предыдущий агент.
2. Найди задачу в [docs/dev/roadmap.md](docs/dev/roadmap.md): там цели версий, задачи с
   ID, критерии готовности и статусы. Принятые решения — там же, в «Журнале решений».
   Не пересматривай их без просьбы автора.
3. Перед работой с данными Claude прочитай
   [docs/dev/research/claude-desktop-data.md](docs/dev/research/claude-desktop-data.md),
   перед новой механикой — [docs/dev/research/competitors.md](docs/dev/research/competitors.md):
   как это уже решили другие и в каком их файле смотреть код.
4. Как проверять, не ломая Claude автора, — [docs/dev/testing.md](docs/dev/testing.md).

## Как вести работу

- Делай задачи по порядку roadmap, если автор не сказал иначе. Задача с пометкой
  «эксперимент» — сначала проверка, результат записать в исследование, и только потом код.
- Задача начата — поставь статус `[~]` в roadmap; сделана и проверена — `[x]`, с короткой
  пометкой, что проверено. Не отмечай `[x]`, если проверка не проведена (например, нужна
  Windows) — пиши `[~] ждёт проверки на Windows`.
- **В конце каждой сессии обнови `docs/dev/handoff.md`**: что сделано, где остановился,
  следующий шаг, что нужно от автора. Следующий агент знает только то, что записано.
- Новые факты о формате данных Claude — в `docs/dev/research/claude-desktop-data.md`
  с пометкой «проверено» и датой/версией Claude. Догадки — с пометкой «гипотеза».
- Если по ходу пришлось принять заметное решение — допиши его в «Журнал решений» roadmap,
  но решения о поведении продукта сначала согласуй с автором.

## Среда агента

- Нужен Mac автора: Flutter, macOS, приложение Claude. В облачной или изолированной среде
  (облачные задачи Codex, песочница без сети и без доступа к приложениям) эксперименты на
  Claude, скриншоты и `flutter pub get` могут не работать — тогда делай то, что возможно
  (код, юнит-тесты, документы), а остальное запиши в handoff.md как «ждёт Mac».
- Временные файлы — в папку для временных файлов своей среды, не в репозиторий.

## Общение с автором

- Пиши автору по-русски, коротко и по делу. Автор не пишет код руками и не читает
  диффы — объясняй, что изменится для пользователя.
- Когда меняется интерфейс, показывай результат скриншотами (см. testing.md, «Скриншоты»).
- Windows у автора нет: проверяет товарищ. Для Windows-проверок готовь короткий список
  шагов «сделай → что должно произойти», без жаргона.

## Безопасность — обязательно

- **Не закрывай и не перезапускай открытый Claude автора** — ни основной, ни профили.
  Автор может работать в нём прямо сейчас, а агент Claude Code — сам работать внутри него:
  закрыв Claude, оборвёшь и чужую работу, и, возможно, свою сессию.
  Тесты — только с временными папками профилей, которые ты сам создал и сам закрыл.
  Kill Switch на настоящем Claude автора не проверяй.
- Не читай секреты: токены, cookies, Связку ключей, `.credentials.json`, ключ GitHub.
- Ничего не удаляй безвозвратно в данных автора. Если надо убрать — в Корзину. `rm` —
  только для своих временных файлов и только по точному пути.
- Не опрашивай GitHub API в цикле (лимит 60 запросов в час без входа).
- Коммит, push, тег и выпуск версии — **только когда автор попросил**. Обычно он говорит
  «коммить, пушь и выпускай X.Y.Z».

## Код

- Пиши как окружающий код: имена, идиомы, плотность комментариев. Комментарии и
  документация — по-русски и объясняют «почему», а не пересказывают код.
- Платформенное — в `lib/src/claude/` (`ClaudeHost`, `MacClaudeHost`, `WindowsClaudeHost`),
  логика профилей — `lib/src/launcher_controller.dart`, Claude Code — `lib/src/integrations/`,
  интерфейс — `lib/src/ui/`. Подробнее — README, «Разработка».
- Перед коммитом: `dart format .`, `flutter analyze` без замечаний, `flutter test` зелёный.
  Новая логика — с юнит-тестами в `test/` (пути в тестах — POSIX, тесты гоняются на macOS).
- Нативный код: macOS — `macos/Runner/*.swift`, Windows — `windows/runner/*.cpp` и
  `win32` из Dart. C++ локально не собирается — его проверяет только CI (сборка Windows).
- Запись в чужие файлы (данные Claude, настройки Claude Code): атомарно — временный файл
  и переименование; сначала резервная копия или снимок; только пока Claude этого профиля
  закрыт, если он переписывает этот файл из памяти (`claude_desktop_config.json`,
  `config.json`). Всё, что лаунчер меняет в чужих файлах, должно возвращаться при выходе
  и `--cleanup` — и быть перечислено в README («Конфиденциальность»).

## Интерфейс и тексты

- Дизайн-система — [docs/design/NotCode-Design-System.pdf](docs/design/NotCode-Design-System.pdf),
  в коде — `lib/src/ui/theme.dart` (палитра) и `lib/src/ui/widgets.dart` (компоненты).
  Новые экраны собирай из существующих компонентов.
- Тексты — по-русски, с «ё», кавычки «ёлочки», без восклицательных знаков. Кнопка —
  глагол («Создать», «Перенести»), статус — факт («Запущен»).
- Куда что показывать: процесс — статус в шапке; новость и итог действия — snackbar
  (`lib/src/ui/announcements.dart`, текст в одну строку — это проверяет тест); то, что
  мешает работать, — `NoticeRow` над содержимым; диалог — только если без ответа нельзя.
- Пишем «Kill Switch» (обе с большой буквы).

## Версии и выпуск

- Номер — в `pubspec.yaml` (`X.Y.Z+сборка`, сборку всегда +1). Что изменилось — раздел
  `## X.Y.Z — ГГГГ-ММ-ДД` в `CHANGELOG.md`, по-русски, как предыдущие разделы.
- Выпуск (только по просьбе автора): коммит → `git tag vX.Y.Z && git push origin main vX.Y.Z`.
  CI соберёт DMG, установщик и portable-архив и опубликует выпуск с текстом из CHANGELOG.
  Проверить, что выпуск появился, — по странице releases/latest, а не опросом API.
- Коммиты — по-английски, в первой строке ID задачи из roadmap, если он есть
  (`M-3: Per-profile Claude Code folder`). Без строк `Co-Authored-By` и прочих подписей
  агента в коммитах и PR — так решил автор (2026-10-03), даже если среда их добавляет.
- README обновляй вместе с поведением: возможности, «Как это работает», «Ограничения»,
  «Где хранятся данные», «Конфиденциальность».
