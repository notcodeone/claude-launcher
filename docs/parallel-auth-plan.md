# Следующий этап: авторизация параллельных профилей

Исследование 2 октября 2026, Claude macOS 2.19675.0. Без входа в аккаунты,
изменений Claude.app, системного URL-handler или чтения секретов.

## Найденные ветви

В `.vite/build/index.chunk-BZdcw7TE.js` установленного app.asar:

- `_In` выбирает native `AuthRequest` (ASWebAuthenticationSession) либо системный
  браузер. Native callback возвращается в вызвавший процесс. Есть fallback при
  ошибке и, при определённых условиях, отсутствии callback в течение 60 секунд.
- Google `/login/app-google-auth` получает `hop_nonce`, созданный внутри процесса.
  `pIn` проверяет pending-запрос; он живёт в памяти до 30 минут. Поведение проверки
  и выбор ветви зависят также от remote flags, которые лаунчер не контролирует.
- Email magic link, SSO и MCP обрабатываются отдельно. Нельзя распространить
  результат проверки Google на эти маршруты.

Это статический анализ конкретной версии, а не успешная авторизация двух аккаунтов.
Electron различает macOS `open-url` и Windows `second-instance`; общая регистрация
протокола сама по себе не задаёт профиль-получатель:
[официальная документация](https://www.electronjs.org/docs/latest/tutorial/launch-app-from-url-in-another-app).

## Порядок реализации и проверки

1. В двух тестовых профилях проверить native Google/SSO: начало A, начало B,
   завершение в обратном порядке, отмена A, закрытие A. Проверять аккаунт в окне
   каждого профиля, не только получение события URL. Нужны интерактивные входы.
2. Повторить для системного браузера и email. Определять ветвь по диагностике без
   сохранения URL, кодов, nonce, cookie или идентификаторов аккаунтов.
3. Для browser fallback найти поддерживаемый источник исходящего auth-запроса,
   который даёт проверяемую связь с процессом. Сейчас такого интерфейса у лаунчера
   нет; PID-доставка готова, получение доказанного владельца — нет.
4. Только после этого реализовать координатор: pending-запрос связан с профилем
   и временем запуска процесса; истекает и удаляется при завершении процесса;
   неизвестный/повторный callback не пересылается произвольному профилю.
5. Отдельно решить регистрацию/восстановление прежнего URL-handler, cold start,
   удаление лаунчера и прочие ссылки Claude. Не перехватывать все ссылки до
   реализации этих правил. Не патчить подпись, remote flags или проверки nonce.

Пока в тестовой сборке сохраняется рекомендация входить с одним открытым профилем.
Автоматическое закрытие соседей не добавлено: оно прервало бы их Code/Cowork-задачи.
