# Первый тест двух агентов — macOS и Windows

Тестовая версия: 1.5.10-parallelism.8. Начать с двух профилей, затем двух задач.
Выполнять один и тот же сценарий отдельно на каждой ОС.

## Установка

- macOS: DMG из тестовой сборки, перетащить ClaudeLauncher в «Программы».
- Windows: установщик `ClaudeLauncher-Setup-1.5.10-parallelism.8.exe` либо
  `ClaudeLauncher-windows-portable.zip`. Переносную версию распаковать целиком,
  запустить `claude_launcher.exe`, DLL и data оставить рядом.
- Сборки GitHub Actions: выбрать успешный запуск Build для ветки parallelism,
  раздел Artifacts. Для скачивания артефактов может потребоваться вход в GitHub.

Тестовая сборка использует существующие профили и настройки лаунчера. Запустить
один экземпляр лаунчера. Для теста создать два отдельных профиля «Тест A» и «Тест B».

## Подготовка аккаунтов

1. Открыть A, выполнить вход вручную, проверить аккаунт в Claude, затем закрыть A.
2. Открыть B, войти во второй аккаунт, проверить его и закрыть B.
3. Настройки → Эксперименты → «Параллельные профили — тест» → включить.
4. Открыть A и B. Оба должны остаться запущенными. Поочерёдно выбрать «Показать»
   у каждого и проверить аккаунт. Вход в рамках этой первой проверки выполняется
   последовательно: маршрутизация одновременного входа пока не подтверждена.

## Две задачи

1. Создать две пустые папки для теста. В A разрешить доступ только к папке A,
   в B — только к папке B.
2. В Cowork A попросить создать `result-A.txt` с текстом `PROFILE A`.
   Одновременно в Cowork B — `result-B.txt` с текстом `PROFILE B`.
3. Проверить результаты, аккаунты и папки. Затем запустить более длительную задачу
   B на тестовых данных и закрыть A через лаунчер. B должен продолжить работу.
4. Повторно открыть A: B остаётся открытым. Повторить с перестановкой A/B.
5. Повторить аналогичный цикл для Code: запрос разрешения, завершение,
   уведомление. На macOS проверить переход из карточки сессии. На Windows
   при двух экземплярах перейти к сессии внутри Claude: адресные ссылки лаунчера
   пока отключены.

Совместимость одновременного Cowork ещё проверяется. Если VM, разрешение или
аккаунт не соответствуют профилю, зафиксировать шаг и остановить этот сценарий.
Не считать успешный запуск двух окон подтверждением двух независимых Cowork-задач.

## Отчёт

В лаунчере: Настройки → Эксперименты → «Отчёт параллельных профилей» →
«Копировать отчёт». Профили обозначены номерами в порядке списка. Отчёт содержит
версию, PID, количество Code-сессий и результат проверки настройки прокси.
Имена аккаунтов, пути, ID сессий, текст задач и токены не включены; автоматической
отправки нет. Сохранить отчёт до начала задач и после проблемного шага.

К результату достаточно добавить:

- ОС и версия установленного Claude; для Cowork — локальный или облачный режим.
- Номер шага; ожидаемое и фактическое поведение.
- Продолжил ли соседний профиль работу после закрытия другого.
- Отчёт лаунчера; переписка и данные аккаунтов не нужны.

Проверка прокси в отчёте относится к файлу конфигурации. Она не подтверждает
фактическую защиту всего трафика VM, MCP и облачных задач. Испытания обрыва сети
и передачи охраннику следует проводить отдельным этапом после базового сценария.
