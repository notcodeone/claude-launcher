# Проверка параллельных профилей на Windows

3 октября 2026. Проба транспорта пока не подключена к WindowsClaudeHost.
`supportsTargetedLinks` остаётся false: приложение блокирует переходы при нескольких
экземплярах. Fake-тесты и статический анализ не подтверждают работу native API.

## Условия

Windows с установленным Claude, Dart из Flutter SDK и зависимости проекта.
Два тестовых профиля A/B с разными явными `--user-data-dir`. Использовать
существующую Code-сессию из B: `claude://claude.ai/epitaxy/<hostSessionId>`.
Не использовать ссылки входа: проба отвергает авторизацию, query и fragment.

Сведения о процессах можно посмотреть локально:

```powershell
Get-CimInstance Win32_Process -Filter "Name = 'Claude.exe'" | Select-Object ProcessId,ExecutablePath,CommandLine
```

Основной процесс не содержит `--type=`. Не публиковать полный вывод с путями
пользовательских профилей. Проба также читает CreationDate, чтобы обнаружить
переиспользование PID; сведения и URL не пишет в файлы и не выводит.

## Показ окна

```powershell
dart run tool/window_activation_probe.dart <PID-B>
```

Проверить B видимым, свёрнутым и скрытым в трее. A остаётся открытым; новых
процессов не возникает. Сопоставить выбранный профиль визуально. Отказ Windows
в фокусе считается отдельным результатом, а не причиной повторно запускать exe.

## Доставка ссылки

```powershell
dart run tool/windows_link_probe.dart <PID-B> 'C:\test\Claude-B' 'claude://claude.ai/epitaxy/<hostSessionId-B>'
```

Проба проверяет исполняемый файл Desktop, папку и время создания процесса;
находит ровно один Chrome_MessageWindow с названием папки, проверяет PID,
класс и название HWND непосредственно перед отправкой. Если найдено два окна,
отказывает независимо от их владельцев. Затем отправляет один WM_COPYDATA
с UTF-16 START/cwd/command-line и ждёт ответ до двух секунд с ABORTIFHUNG и
ERRORONEXIT. Пакет содержит только executable, `--user-data-dir` и ссылку Code;
additional_data отсутствует. Повтор, запуск exe, системный URL-handler и
завершение процесса не используются, включая отсутствие ответа: ссылка могла
быть доставлена до тайм-аута.

ACK означает лишь ответ получателя. Успех требует визуально подтвердить,
что нужная сессия открылась в B, профиль A сохранил свою сессию и число процессов
не изменилось. Проба не адресует основной MSIX-профиль без `--user-data-dir`:
виртуализированный путь нельзя надёжно вывести из APPDATA. Для этого нужен
отдельный источник соответствия PID → фактический userData.

## Матрица для записи результатов

Все native-сценарии ниже **ещё не выполнены**; Windows в текущей среде отсутствует.

| Сценарий | Ожидаемый результат |
| --- | --- |
| A и B открыты, URL B → PID B | B открывает свою сессию; A и число процессов прежние |
| URL A → PID A | Симметричный результат |
| B свёрнут / скрыт в трее | Адресность сохраняется; показ/фокус проверяются отдельно |
| B закрыт перед отправкой | Отказ, без запуска нового экземпляра |
| Папка A + PID B | Отказ до отправки |
| Два receiver HWND одной папки | Отказ до отправки |
| Получатель не отвечает | Ограниченное ожидание, без повторной доставки |
| Unicode и пробелы в пути | Точная передача путей и той же сессии |
| MSIX из Store / пакет с сайта | Отдельная запись версии и результата каждого |
| Основной профиль без флага папки | Сейчас отказ; production-поддержка не включается |

Записывать только версию Claude/Windows, вид установки и PASS/FAIL с категорией
ошибки; без полного URL, идентификатора сессии, учётной записи или командной строки.
После подтверждения версии протокола и матрицы можно подключать адресный транспорт
к хосту приложения. Ошибки адресной доставки должны оставаться явными и не иметь
fallback к общему обработчику.

## Основания протокола

- [Chromium MessageWindow: message-only HWND, класс и название папки](https://raw.githubusercontent.com/chromium/chromium/main/base/win/message_window.cc)
- [Electron ProcessSingleton: дополнительное поле Windows, текущая main](https://github.com/electron/electron/blob/main/patches/chromium/feat_add_data_parameter_to_processsingleton.patch)
- [Microsoft SendMessageTimeout: ограничения ожидания и ошибки](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw)

Эти исходники описывают кандидат протокола, а не доказывают соответствие конкретному
Claude Windows. Изученная локальная версия Electron 44.4.3 относится к Claude macOS;
версию framework Windows ещё требуется установить и проверить.
