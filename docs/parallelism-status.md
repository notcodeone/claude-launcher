# Состояние ветки parallelism — разработка приостановлена

3 октября 2026. База: `72bb1c6` (1.5.9). Версия: `1.5.10-parallelism.9+31`.
Подробности реализации, исследование Claude и таблица совместимости —
в [parallel-profiles.md](parallel-profiles.md); здесь только итог и что делать
при возобновлении.

## Что работает

Эксперимент «Параллельные профили — тест» (Настройки → Эксперименты, выключен
по умолчанию):

- Запуск профиля сохраняет открытые; показ и закрытие адресованы PID профиля.
  Операции с профилями сериализованы, обслуживание (обновление Claude, автозапуск
  набора) резервирует их целиком; Kill Switch прерывает его.
- Автозапуск выбранного набора профилей, последовательно, со строгой проверкой
  каждого; остановка на первом отказе.
- macOS: ссылки `claude://` — Apple Event `GURL` конкретному PID, без перехода на
  системный обработчик. Windows: при нескольких экземплярах переходы заблокированы.
- Сессии Code привязываются к профилю по метаданным Claude (оба ID), задержанные
  события дожидаются метаданных, недавние сессии восстанавливаются после
  перезапуска лаунчера. Неоднозначный владелец — без привязки.
- Встроенное обновление Claude у запускаемых профилей выключено; Claude обновляет
  лаунчер: закрывает все профили, ставит, открывает их снова.
- Kill Switch учитывает каждый процесс; конфигурация прокси проверяется целиком.
- Отчёт параллельных профилей без персональных данных (схема 2: добавлено
  состояние удержания обновлений).

## Известные ограничения

- **Вход в аккаунт** — только при одном открытом профиле. Системный обработчик
  `claude://` общий; лаунчер не видит исходящий запрос входа. Это ограничение
  Claude, а не реализации. План — [parallel-auth-plan.md](parallel-auth-plan.md).
- **Windows** — показ окна по PID и проба транспорта ссылок проверены только
  fake-тестами; проба не подключена к приложению.
  Матрица — [windows-parallel-verification.md](windows-parallel-verification.md).
- **Cowork** — одновременные задачи не проверялись. Аудит защиты —
  [parallel-protection-audit.md](parallel-protection-audit.md).
- Профили, открытые до включения режима или вне лаунчера, обновляются сами до
  перезапуска. Kill Switch проверяет файлы конфигурации, а не фактический трафик.
- Операции глобально сериализованы: пока запускается один профиль, с другим
  ничего сделать нельзя. При необходимости — блокировка по профилю внутри
  `LauncherController`, без переделки остального.
- Подписанная сборка (hardened runtime): entitlement и описание Apple Events
  объявлены, но `tool/make_dmg.sh` переподписывает ad-hoc без `--entitlements`;
  при переходе на постоянную подпись передать entitlements явно.
