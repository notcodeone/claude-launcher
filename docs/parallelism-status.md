# Состояние тестовой ветки parallelism

3 октября 2026. База: `72bb1c6`. Версия: `1.5.10-parallelism.7+29`.

## Сделано

- Экспериментальный параллельный запуск, показ и адресное закрытие профиля.
- Защита от пересекающихся запусков. На macOS переходы адресуются PID через
  Apple Event с проверкой схемы и bundle ID.
- Переходы требуют свежего успешного сканирования. Ошибка чтения процессов
  блокирует отправку по старому списку, а несколько процессов одной папки не
  дают произвольного выбора получателя.
- Отдельная проба Windows WM_COPYDATA: PID/папка/CreationDate, единственный
  Chrome_MessageWindow, повторная проверка HWND, UTF-16 framing и ожидание до двух
  секунд без повтора/fallback. Только Code URL и явный userData; не подключена к
  приложению и ещё не выполнена на Windows. [Матрица проверки](windows-parallel-verification.md).
- Windows: показ окна по PID вместо повторного запуска exe. Проверяются папка
  процесса, основное HWND и владелец перед показом; скрытое окно показывается,
  свёрнутое восстанавливается. Отказ фокуса сообщается пользователю. Native-часть
  ещё не проверена на Windows; добавлена отдельная проба для живой проверки.
  Ошибка/переполнение EnumProcesses и нечитаемая командная строка обнаруженного
  Claude не считаются отсутствием экземпляров.
- Параллельный автозапуск выбранного набора, отдельного от одиночного профиля.
  Миграция прежнего ID, удаление из обоих вариантов, последовательный запуск со
  строгой проверкой каждого, резервирование операций, остановка при ошибке и Kill
  Switch. Уже открытый Claude отменяет весь набор. Строгое сканирование не допускает
  запуск на устаревшем списке при отказе чтения процессов.
- Сессии Code определяются по профильным метаданным: сверяются оба ID среди всех
  профилей, включая закрытые. Дубликаты, повреждённые записи и симлинки не дают
  произвольной привязки. Уведомления адресуются исходному профилю.
- Задержанные события Code: до 256 событий на две минуты в памяти, проверка каждые
  две секунды, исходный порядок и без повторных уведомлений. Перезапущенный процесс
  не наследует старые события.
- Восстановление недавних Code-сессий после перезапуска лаунчера: до 256 ссылок не
  старше часа, повторная проверка владельца по данным Claude. Состояние до нового
  события — «Неизвестно». Реестр хранит только ID и время; названия, пути, переписка,
  текст уведомлений и токены в нём отсутствуют. Отключение событий очищает реестр.
- Общая блокировка операций с профилями на время закрытия, установки обновления
  Claude и восстановления окон. Снимок профилей не зависит от последующей смены
  режима. Ошибка одного восстановления не пропускает остальные.
- Отказ установки восстанавливает профили только при подтверждённой пригодности
  приложения. На macOS проверяются версия и codesign; Windows пока не подтверждает
  автоматическое восстановление после неуспешной установки. Неизвестный экземпляр
  и ошибка чтения списка процессов блокируют установку. Аварийное закрытие отменяет
  автоматическое восстановление.
- Резервная копия Claude macOS не удаляется, если откат также завершился ошибкой;
  повторная установка блокируется до ручного восстановления копии.
- Проверка прокси сверяет собственную запись, loopback URL, порт затвора,
  disableAutoUpdates и режим 1p; одного appliedId недостаточно. Новый процесс
  с другим портом требует перезапуска, даже если файл позже исправлен.
- Pin/read/unpin общей папки сериализованы между объектами внутри процесса;
  запись через уникальный временный каталог. Повреждённые/не-объектные JSON,
  симлинки и файлы больше 1 МиБ дают отказ. Чужие настройки не перезаписываются
  и не удаляются. [Аудит защиты/Cowork и оставшиеся проверки](parallel-protection-audit.md).
- Kill Switch учитывает каждый процесс, включая новый экземпляр, появившийся после
  включения защиты. Изменение конфигурации уже работающего процесса не снимает
  требование перезапуска. Чтение настройки прокси не доказывает фактический маршрут
  всех сетевых соединений и Cowork VM.
- Защита предварительной сборки от стабильного канала обновлений, включая macOS
  номер `1.5.10.7`, в который Flutter преобразует предварительную версию.
- [Исследование полной поддержки](parallel-profiles.md), [план входа](parallel-auth-plan.md)
  и воспроизводимые инструменты проверки.

## Проверено

- `flutter analyze --no-pub`: без замечаний.
- Полный набор: **274 теста прошли**. Release-сборка macOS выполнена;
  universal binary **arm64 + x86_64**.
- Конфигурация прокси на временных файлах: неверный порт/URL, отсутствующая
  запись, отсутствие disableAutoUpdates, 3p, malformed JSON, симлинк, размер, чужой
  appliedId и пересекающиеся pin/read/unpin общей папки. Интеграция Kill Switch
  с реальным локальным затвором: соседний профиль с другим портом сохраняет
  требование перезапуска до закрытия этого процесса.
- Windows probe fake-тесты: frame/Unicode/экранирование аргументов, чужая папка,
  отсутствие и дубликаты receiver, смена процесса/папки/exe и повторное использование
  PID, отказ ответа без повтора, запрет auth/чужих URL, размер и допустимость путей.
  Контроллер: отказ свежего сканирования и неоднозначный экземпляр одного профиля.
- Автозапуск набора: миграция/пустой набор/дубликаты, строгая защита каждого,
  внешний экземпляр, ошибки сканирования до и после резервирования, отказ второй
  защиты, аварийное закрытие, смена режима и блокировка конкурирующей операции.
  Windows fake-тесты адресности окна, восстановления и отказа фокуса.
- Тесты отказов установки, отката, запуска одного профиля, отмены закрытия,
  аварийного завершения, смены режима и недоступного списка процессов.
- Перезапуск интеграции Code без новых уведомлений; закрытый профиль, копия
  метаданных, неправильный владелец и повреждённый реестр; повтор записи после IO
  ошибки, ограничение размера и срока, очистка и неизвестное состояние в интерфейсе.
- Два AppKit-приёмника ранее подтвердили адресность production-диспетчера Apple
  Events; реальный Claude в двух временных профилях принял отправку без нового
  процесса. Открытие содержимого авторизованной сессии этим тестом не проверялось.
- Живой тест Claude 2.19675.0 на macOS: два временных профиля работают одновременно;
  закрытие одного не затрагивает другой и ранее открытые процессы. Тестовые процессы
  закрыты, временные каталоги удалены. Повторный низкоуровневый запуск той же папки
  создавал дубликат; лаунчер использует показ по PID и свою блокировку операций.
- Отказы замены macOS-приложения проверены на искусственных каталогах. Реальное
  установленное Claude при этих проверках не заменялось и не обновлялось.

## Образ

`build/installer/ClaudeLauncher-1.5.10-parallelism.7.dmg`

Размер: около 21 МБ. `hdiutil verify` — VALID; `codesign --verify --deep --strict`
для приложения внутри смонтированного DMG — успешно (ad-hoc). Проверены версия
`1.5.10.7` и архитектуры arm64 + x86_64.
SHA-256: `3652deb98860dfeec100b15b9c10269eb88020dee0e2eced21ab655375c5f6f1`.

Включение: Настройки → Эксперименты → Параллельные профили.
Сборка использует существующие настройки и профили лаунчера. Основное приложение
в `/Applications` автоматически не заменяется; устанавливается пользователем.

## Осталось до полноценной поддержки

1. Проверить вход двумя аккаунтами через native ASWebAuthenticationSession и отдельно
   через системный браузер; получить проверяемую связь исходящего browser auth-flow
   с профилем. Лаунчер пока не получает исходящий запрос и не перехватывает callbacks.
2. Дополнительные форматы Code (SSH/cloud/import), более длительные пропуски событий,
   текущие состояния и названия задач при отсутствии свежего хука после перезапуска.
3. Авторизованные испытания двух Cowork-задач, общих служб и интеграций.
4. Полная Windows/MSIX-матрица: живая проверка нового показа по PID и транспорта
   URL; безопасное восстановление после ошибки MSIX-установки.
5. Аудит фактического трафика каждого экземпляра и VM, внешних запусков, передачи
   охраннику, изменения порта и аварийного восстановления. Проверка настройки не
   подменяет проверку соединений.
6. Реальные установщики и встроенное обновление Claude при нескольких процессах;
   запуск извне в середине установки. Блокировка действует на операции лаунчера.
7. Живая проверка автозапуска набора, глобальные горячие клавиши, Dock и длительные нагрузки.

Вход пока проверять при единственном открытом профиле. На Windows при нескольких
экземплярах переходы к сессиям заблокированы. Cowork не объявлен совместимым.
