# Как проверять

Главное правило: **открытый Claude автора не закрывать и не перезапускать**. Агент
может работать внутри него — закрыв Claude, ты оборвёшь и свою сессию, и работу автора.

## Обычная проверка

```bash
dart format .
flutter analyze
flutter test
```

Новая логика — с юнит-тестами в `test/`. Данные Claude в тестах — фикстуры во временной
папке (`Directory.systemTemp.createTemp`), не настоящие папки автора. Пути в тестах —
POSIX: тесты гоняются на macOS и в CI на macOS.

## На настоящем Claude (macOS)

`integration_test/macos_host_test.dart` — образец: запускает **отдельный** профиль Claude
во временной папке, находит его, закрывает и удаляет папку. Уже открытый Claude не
трогается:

```bash
flutter test integration_test/macos_host_test.dart -d macos
```

Так же делай свои проверки: свой временный `--user-data-dir`, второй экземпляр через
`open -n`, закрытие только своего pid.

Временный профиль не вошёл в аккаунт — в нём не открыть вкладку Code. Где нужен вход
(эксперименты M-E1, M-E3, S-9), действуй так:
1. Спроси автора, какой его профиль можно запустить вторым экземпляром.
2. Запусти его рядом с открытым Claude (`open -n` или способом из M-E2), не закрывая
   основной.
3. Попроси автора сделать в нём нужное действие (открыть сессию, написать сообщение).
4. Смотри только имена файлов и время изменения — не содержимое переписок и не токены.
5. Закрой только этот экземпляр (по его pid) и скажи автору, что закрыл.

Поставить собранный лаунчер вместо установленного (когда автор попросил) — только
`flutter build macos --release && tool/install_local.sh`. Скрипт дожидается полного выхода
лаунчера: при Kill Switch тот передаёт затвор фоновому процессу, и подмена приложения
посреди выхода оставляет Claude без сети, а лаунчер — без иконок (так было 2026-10-03).
Не удаляй и не подменяй `/Applications/ClaudeLauncher.app` вручную.

Запускать собранный из исходников лаунчер (`flutter run -d macos`) — только если автор
попросил: он работает с настоящими профилями и может их переключать. Ничего не
переключай в нём сам.

## Профиль для проверок Code

Второго профиля с доступом к Code у автора нет: «Личный» — на бесплатном плане, а
вкладка Code нужна платная. Для проверок, где нужна вкладка Code в профиле лаунчера
(M-9, S-9, параллельный запуск), — тестовый профиль «Тест», вошедший в **тот же платный
аккаунт**, что и основной. Один аккаунт в двух профилях — это как вход с двух устройств.

- Создаёт и входит автор сам. Пока лаунчер открывает один профиль за раз (до 1.7),
  открытие «Теста» закроет основной Claude — и сессию агента, если он работает внутри
  Claude. Поэтому автор делает это, когда в основном Claude не идёт работа.
- Проверку агент готовит заранее: что сделать в «Тесте» и какие файлы потом посмотреть.
  Результат автор сообщает агенту (или следующему агенту через handoff.md).
- Вход второго профиля в тот же аккаунт ничего не меняет в основном профиле.

## Windows

У автора нет Windows — проверяет товарищ. C++ в `windows/runner` собирает только CI.
Для проверки готовь автору сообщение для товарища:

```
Версия: ClaudeLauncher X.Y.Z (поставить: irm https://raw.githubusercontent.com/notcodeone/claude-launcher/main/tool/install.ps1 | iex)

1. Сделай: …
   Должно быть: …
2. …

Если что-то не так — скриншот и файл %TEMP%\… (какой именно журнал).
```

Шаги — «сделай → что должно произойти», без жаргона. Если нужна сборка до выпуска —
артефакты CI (Actions → Build → установщик), но их скачивание требует входа в GitHub.

## Скриншоты для автора

Интерфейс показываем скриншотами из виджет-тестов, без запуска приложения:

- временный тест рендерит страницу в окне 560 × 640 в светлой и тёмной теме;
- шрифт — системный SF, как в `test/notices_test.dart` (`FontLoader('Roboto')` из
  `/System/Library/Fonts/SFNS.ttf`), иначе в тестах квадратные буквы;
- `RepaintBoundary` → `toImage(pixelRatio: 2)` → PNG в папку для временных файлов
  сессии, показать автору;
- `FileImage` в тестах не декодируется — картинки подставлять через `MemoryImage`;
- такой тест не коммитить.
