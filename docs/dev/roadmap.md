## 1.5.10 — надёжность

Небольшой выпуск. Можно делать параллельно с экспериментами для 1.6.0.

### [~] A-1. Бережное закрытие Claude на Windows — код готов, ждёт проверки на Windows
**Зачем.** Сейчас, если Claude за 5 секунд не вышел сам, лаунчер завершает его
принудительно (`WindowsClaudeHost.autoForceQuitAfter`) — это может оборвать сессии Code и
Cowork. При закрытии окна Claude уходит в трей, а `taskkill` без `/F` делает то же самое.

**Как.** Так же, как claude-switcher (см. competitors.md, «Бережное закрытие на Windows»):
1. Дождаться, пока этот запуск Claude закончит загрузку: в его `logs/main.log` появилась
   строка `boot: done` со временем не раньше старта процесса (не дольше 30 с). Если
   сообщение о выходе приходит во время загрузки, Claude завершается без своей уборки.
   Где лежит `main.log` у профиля и у пакета MSIX — проверить (эксперимент A-1a).
2. Всем окнам верхнего уровня главного процесса (`EnumWindows` + `GetWindowThreadProcessId`)
   послать `WM_QUERYENDSESSION`, затем `WM_ENDSESSION(wParam=TRUE)` через
   `SendMessageTimeout(SMTO_ABORTIFHUNG, 3000)`. В логе Claude будет
   `Windows session ending (shutdown) - quitting the app`.
3. Ждать выхода до 30 с. Не вышел — состояние `waitingForUser` с кнопкой «Закрыть
   принудительно», как на macOS. `autoForceQuitAfter` убрать (вернуть `null`).

**Где.** `lib/src/claude/windows_claude_host.dart` (`requestQuit`, `autoForceQuitAfter`),
`lib/src/launcher_controller.dart` (`_closeAll`), README «Ограничения».

**Готово, когда.** На Windows переключение профиля закрывает Claude без принудительного
завершения: в его `main.log` есть строка о штатном выходе, сессия Code после повторного
открытия на месте. Проверено товарищем на Windows.

### [~] A-2. Контрольные суммы SHA-256 — код готов, проверится выпуском 1.5.10
- CI в задаче `release` публикует `SHA256SUMS.txt` для всех файлов выпуска.
- `lib/src/updates/app_updater.dart` перед установкой сверяет скачанный файл с суммой.
  Нет файла сумм (старый выпуск) — ставим как раньше; сумма не сошлась — не ставим,
  показываем причину.
- `tool/install.sh` и `tool/install.ps1` сверяют сумму так же.

**Готово, когда.** Тест на сверку сумм; в выпуске 1.5.10 есть `SHA256SUMS.txt`, а
обновление с 1.5.9 до 1.5.10 проходит.

### [x] A-3. README: куда пишет лаунчер и чего не показывает
Раздел со списком всех мест, куда лаунчер пишет (папки, файлы чужих приложений, реестр,
правило брандмауэра), и что он возвращает при выходе. Отдельно — «Чего лаунчер не делает»:
не читает токены и cookies, не обходит лимиты, не обновляет чужие входы.

### [~] A-4. Проверка на Windows того, что вышло в 1.5.9 — список для товарища в handoff.md
Подготовить автору список для товарища: правило Cowork в брандмауэре не мешает Cowork

Claude в трее прячется настройкой `menuBarEnabled`. Найденное — исправить в 1.5.10.

## 1.6.0 — раздельная память Claude Code

**Проблема.** Вкладка Code в Claude всех профилей пишет в одну папку `~/.claude`:
память проектов (`projects/<проект>/memory`), глобальный `CLAUDE.md`, переписку,
историю, `settings.json` с разрешениями, плагины. Работа рабочего аккаунта видна личному.
Память чатов (на сервере у аккаунта) и, по исследованию, Cowork (своя копия Claude Code
внутри песочницы в папке профиля) уже разделены — подтвердить в M-E4.

**Решение.** Запускать Claude профиля с `CLAUDE_CONFIG_DIR=<папка профиля>/claude-code`.
Claude передаёт окружение вкладке Code, и та хранит всё в папке профиля.

### Эксперименты — до кода
Все — на временных или явно разрешённых автором профилях, не закрывая основной Claude
(см. testing.md). Результаты — в `research/claude-desktop-data.md`, раздел «Claude Code
внутри Desktop».

- [x] **M-E1. Видит ли вкладка Code переменную.** Да — по коду Claude 2.19675.0 (research, «Claude Code внутри Desktop»); живая проверка — в M-9. Запустить второй экземпляр Claude с уже
  вошедшим профилем (какой — спросить автора) и `CLAUDE_CONFIG_DIR=<временная папка>`.
  Автор открывает сессию Code и пишет одно сообщение. Ожидаем: переписка, `settings.json`,
  `.claude.json` появились во временной папке, а не в `~/.claude`.
- [~] **M-E2. Как передать окружение на macOS.** `open -n --env` работает на macOS 26 (проверено); старые macOS — не проверено, нужен запасной путь. `open -n` переменные не передаёт. Варианты:
  `open -n --env VAR=… -a Claude.app --args …` (проверить, есть ли `--env` на поддерживаемых
  macOS — у нас от 10.15) или прямой запуск `Claude.app/Contents/MacOS/Claude` с окружением
  (так делает claude-profile-manager). Проверить, что при прямом запуске Dock, активация
  окна, `NSRunningApplication.terminate` и наш поиск экземпляров работают как с `open -n`.
- [x] **M-E3. Вход во вкладке Code.** Вход передаёт сам Claude (`CLAUDE_CODE_OAUTH_TOKEN`), от папки не зависит — по коду. Не просит ли Code войти заново с новой папкой; откуда
  он берёт вход (передаёт ли его Desktop). Читать сами токены нельзя — смотрим только
  поведение и имена файлов.
- [ ] **M-E4. Что ещё пишется в `~/.claude` и `~/.claude.json`** при работе с новой папкой
  (по времени изменения файлов). Подтвердить, что Cowork не трогает `~/.claude`.
- [~] **M-E5. Общие `CLAUDE.md`, навыки, агенты, команды.** По коду: ссылки на папки внутри папки Claude Code ломают запись Claude — см. research; решение для навыков — в M-3. Проверить: (а) `CLAUDE.md`
  профиля из одной строки `@~/.claude/CLAUDE.md` (импорт Claude Code) подтягивает общий
  файл; (б) папки `skills`, `agents`, `commands` как символическая ссылка (macOS) и
  junction (Windows, без прав администратора) читаются вкладкой Code.
- [ ] **M-E6. Windows** (товарищ): переменная доходит при прямом запуске `claude.exe`;
  при запуске «через пакет» (`IApplicationActivationManager`) окружение не передаётся —
  проверить, как часто этот путь нужен, и решить запасной вариант. Длина путей:
  `%APPDATA%\Claude-<имя>\claude-code\projects\<закодированный путь>\<id>.jsonl` против
  ограничения 260 символов.

**Если M-E1 не подтвердится** — остановиться и обсудить с автором: без переменной
раздельной памяти через переменную не будет.

### Реализация
- [ ] **M-1. Профиль знает свою папку Claude Code.** `Profile` получает режим памяти:
  «своя» (по умолчанию для новых) или «общая с Основным» (прежнее поведение). Путь —
  `<dataDir>/claude-code`. «Основной» — всегда `~/.claude`.
- [ ] **M-2. Запуск с окружением.** `ClaudeHost.launch(dataDir, {environment})`:
  macOS — способ из M-E2; Windows — `Process.start(environment: …)`, запасной путь — по
  итогам M-E6. При запуске в окружение кладём `CLAUDE_CONFIG_DIR` и больше ничего не
  меняем.
- [ ] **M-3. Подготовка папки.** При первом запуске профиля создать `claude-code/`:
  `CLAUDE.md` с импортом общего (`@<абсолютный путь к ~/.claude/CLAUDE.md>`); агенты и
  команды — ссылками на отдельные файлы (ссылка-файл Claude разрешает); навыки — копией
  папок навыков с досинхронизацией при запуске профиля (ссылка на папку ломает запись,
  research). Своё — пустое. Повторный запуск ничего не ломает (идемпотентно).
- [ ] **M-4. Хуки в каждой папке.** Учесть `code_profile_resolver.dart` из `parallelism`: сейчас в эксперименте профиль события ищется по карточкам сессий; с хуками в папке профиля id приходит в адресе — проще и надёжнее, резолвер остаётся запасным. `ClaudeCodeHooks` ставит хуки в `settings.json` каждого
  профиля, адрес хука несёт id профиля (`…/claude-launcher/v1/event?profile=<id>` или
  сегмент пути). События привязываются к профилю по адресу, а не к «открытому профилю» —
  это нужно и для параллельного запуска в 1.7. Снятие хуков при выходе и `--cleanup` — во
  всех папках. Проверить уведомления (`notification_handoff.dart`).
- [ ] **M-5. Только сессии приложения.** Карточка профиля показывает только сессии с id
  приложения (`local_…`); события из терминала игнорируются. README и тексты — без упоминаний
  терминала.
- [ ] **M-6. Миграция существующих профилей.** Экран «Раздельная память» (при первом
  запуске 1.6.0 и в настройках профиля):
  1. Снимок того, что будет изменено (см. S-5, тот же механизм).
  2. Переписка: для каждой карточки сессии профиля (`claude-code-sessions/…/local_*.json`)
     скопировать `~/.claude/projects/<проект>/<cliSessionId>.jsonl` и папку
     `<cliSessionId>/` рядом (подагенты) в папку профиля. Копировать, не переносить:
     «Основной» не ломается.
  3. Память проектов не принадлежит никому — для каждого проекта с `memory/` автор
     выбирает: оставить только в «Основном», скопировать в профиль, скопировать во все.
  4. Разрешения проектов (`.claude.json`, `settings.local.json`) — по итогам M-E4.
  5. Отчёт: что скопировано и что пропущено; откат возвращает как было.
- [ ] **M-7. Интерфейс.** Переключатель режима памяти в карточке профиля (странице
  правки), пояснение одной строкой, состояние миграции. Скриншоты автору.
- [ ] **M-9. Живая проверка.** Нужен второй профиль с доступом к Code. У автора его нет
  («Личный» — бесплатный), поэтому — тестовый профиль, вошедший в тот же платный аккаунт,
  что и основной (см. testing.md, «Профиль для проверок Code»). Проверить: новая сессия
  пишет переписку и память в папку профиля; основной их не видит; хуки и уведомления — в
  своём профиле.
- [ ] **M-8. README и CHANGELOG.** «Где хранятся данные», «Как это работает»,
  «Конфиденциальность» (новые места записи).

**Готово, когда.** Новая сессия Code в профиле пишет переписку и память в его папку;
другой профиль её не видит; уведомления и карточки приходят в свой профиль; миграция
существующего профиля проходит и откатывается; на Windows проверено товарищем.

## 1.6.2 — сессии: ручной перенос

- [ ] **S-5. Снимки и журнал.** Общий механизм для всех записей в данные Claude:
  - снимок целевых файлов в `<папка лаунчера>/backups/<профиль>/<время>-<счётчик>/`;
    нет снимка — нет записи; хранить последние 10 на профиль;
  - журнал операции `<папка лаунчера>/journal/<id>/manifest.json`: что было, что стало
    (пути и хеши), статус `planned → writing → done`; незавершённая операция при
    следующем запуске откатывается;
  - «Отменить» последнюю операцию; отказ, если файлы с тех пор изменились.
- [ ] **S-6. План переноса (dry-run).** По выбранным сессиям и целевому профилю строится
  список действий: копировать / пропустить с причиной (уже есть, удалена в целевом,
  нет переписки, незнакомый формат). Пользователь видит его до применения.
- [ ] **S-7. Перенос.** Правила (research, «Правила переноса»):
  - карточка ложится в `claude-code-sessions/<account цели>/<org цели>/` — оба сегмента
    заменить; не определены — перенос в этот профиль недоступен;
  - не переносить, если в цели есть `deleted_<cliSessionId>` или `deleted_<local id>`;
  - дубликат — то же имя файла или тот же `cliSessionId`;
  - из копии убрать `remoteMcpServersConfig`, `enabledMcpTools`, `bridgeSessionIds`,
    `scheduledTaskId`; сбросить `alwaysAllowedReasons`, `sessionPermissionUpdates`,
    `chromePermissionMode`, `chromeTabGroupId`;
  - переписка `<cliSessionId>.jsonl` и папка `<cliSessionId>/` — из папки Claude Code
    источника в папку цели (после 1.6.0 они разные); по выбору — `memory/` проекта;
  - запись — временный файл и переименование, время изменения сохраняется;
  - целевой профиль закрыт; если открыт — предложить закрыть (бережно, A-1).
- [ ] **S-8. Интерфейс переноса.** На странице «Сессии»: выбрать сессии (одну, несколько,
  весь проект) → «Перенести в…» → план → «Перенести» → snackbar с «Отменить».
- [ ] **S-9. Проверка на живом Claude.** С разрешения автора: перенести сессию между
  двумя его профилями, открыть в цели, продолжить разговор. Записать результат.

исследование — [docs/parallel-profiles.md](../parallel-profiles.md), вход —
[docs/parallel-auth-plan.md](../parallel-auth-plan.md), Cowork и Kill Switch —
[docs/parallel-protection-audit.md](../parallel-protection-audit.md), Windows —
[docs/windows-parallel-verification.md](../windows-parallel-verification.md).
При слиянии новое поведение спрятано за экспериментом (`ClaudeHost.parallel`,
`LauncherController.parallelLaunch`): без него — как в 1.5.10 (`open -a` для ссылок на
macOS, повторный запуск для показа окна на Windows, нестрогий опрос процессов, без
ошибки после 20 с запуска, без реестра сессий). Задачи 1.7 ниже — доделать эксперимент
до основного режима; часть уже сделана (P-1, P-3 частично, P-4 частично) — сверяйся со
статусом ветки.

**Цель.** Профили работают одновременно и независимо, без ограничений, кроме тех, что
ставят сам Claude или ОС (о них — честно в интерфейсе).

### Эксперименты — до кода
- [ ] **P-E1. Два экземпляра на macOS.** Временный профиль рядом с открытым Claude:
  оба работают, `running()` видит оба, `activate` и `requestQuit` попадают в нужный.
- [ ] **P-E2. Ссылка в конкретный экземпляр.** macOS: работает ли повторный запуск
  `Claude.app/Contents/MacOS/Claude --user-data-dir=<папка> claude://…` (Electron
  `second-instance`) — сейчас `openLink` делает `open -a`, и macOS выбирает экземпляр
  сама. Windows: тот же приём с `claude.exe` (по коду конкурентов работает).
- [ ] **P-E3. Две машины Cowork одновременно** — macOS и Windows (товарищ). По
  claude-desktop-clone на Windows вторая машина падает с `HYPERVISOR_SERVICE_ERROR`.
- [ ] **P-E4. Обработчик `claude://`** — см. P-5: регистрация, перехват при старте Claude.

### Реализация
- [ ] **P-1. Модель «несколько открытых».** `LauncherController`: «Открыть» больше не
  закрывает другие профили; состояние открытия, закрытия и ошибок — у каждого профиля
  своё. Настройка «Закрывать другие профили при открытии» — для тех, кому нужно прежнее
  поведение (по умолчанию выключена).
- [ ] **P-2. Интерфейс.** Карточки: каждая со своим состоянием и «Показать окно» /
  «Закрыть»; меню значка — список открытых профилей; профиль по умолчанию → «Открывать
  при запуске» может стоять у нескольких профилей.
- [ ] **P-3. Привязка всего к профилю.** Сессии, уведомления (хуки с id профиля, M-4),
  лимиты, нажатие на уведомление — открывают нужный экземпляр.
- [ ] **P-4. Общие действия над всеми.** Обновление Claude — нужно закрыть все экземпляры
  (список, бережное закрытие, вопрос). Kill Switch и проверка страны — действуют на все
  открытые профили.

## 1.7.1 — ссылки `claude://`

- [ ] **P-5. Лаунчер — обработчик `claude://`.** macOS: `CFBundleURLTypes` в Info.plist,
  `LSSetDefaultHandlerForURLScheme`, приём ссылки в `AppDelegate`. Windows:
  `HKCU\Software\Classes\claude` + регистрация в «Приложениях по умолчанию»; если стоит
  чужой `UserChoice` — подсказать, как выбрать лаунчер. Прежний обработчик запомнить и
  вернуть при выключении, выходе и `--cleanup`.
- [ ] **P-6. Возврат роли.** Claude перерегистрирует себя при каждом запуске — лаунчер
  забирает роль обратно (через 2/5/10/20 с после запуска профиля; на Windows — по
  изменению ключа реестра).
- [ ] **P-7. Маршрутизация.** Ссылка на сессию (`epitaxy/local_…`) — в профиль, где эта
  сессия есть. Ссылка входа — в профиль, запущенный последним за 10 минут; иначе — окно
  выбора профиля. Доставка — повторный запуск с `--user-data-dir` и ссылкой (P-E2). Если
  лаунчер не запущен — обработчик запускает его. Запасной путь — «Вставить ссылку входа».
  В журнал — без параметров ссылки (там код входа).
