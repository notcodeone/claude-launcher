### Проверка на Windows 1.7.0 (для товарища; один аккаунт)

Всё делается под одним аккаунтом Claude (можно бесплатным; Cowork — нет, он отложен).
Если шаг не прошёл — скриншот и номер шага, дальше можно не идти.

```
0. Установка
   PowerShell: irm https://raw.githubusercontent.com/notcodeone/claude-launcher/main/tool/install.ps1 | iex
   → «Готово: ClaudeLauncher v1.7.0 установлен».
   В лаунчере: «+» → профиль «Тест» → открыть → войти в аккаунт (через Google).
   Должно быть: в «Тесте» вход есть, стандартный профиль не тронут.

A. Обычный режим (один профиль за раз)
1. В «Тесте» вкладка Code: начни сессию, дождись ответа. Переключись на стандартный профиль.
   → «Тест» закрывается сам за несколько секунд, без «закрыть принудительно».
   Вернись в «Тест» → сессия на месте.
2. Сразу после запуска профиля (первые 5–10 с) переключись на другой.
   → лаунчер подождёт загрузку и закроет так же.
3. В «Тесте» во вкладке Code спроси: «что ты помнишь обо мне?» — и в стандартном тоже.
   → у «Теста» своя память (папка %APPDATA%\Claude-Test\claude-config существует).

B. Несколько профилей сразу
4. Настройки → «Основные» → выключи «Закрывать другие профили при открытии».
   Открой стандартный и «Тест».
   → открыты оба; в меню значка лаунчера у обоих галочки.
5. На карточке «Теста» — «Показать окно Claude». Сверни окно «Теста», нажми ещё раз.
   → выходит окно именно «Теста», окон Claude не прибавляется.
6. Меню карточки «Теста» → «Завершить работу».
   → закрывается только «Тест», стандартный работает.

C. Ссылки claude://
7. Открой «Тест» (последним). Вставь в адресную строку браузера claude://claude.ai/new, Enter.
   Если Windows спросит «Как открыть?» — ClaudeLauncher.
   Если в лаунчере строка «Ссылки Claude открывает не лаунчер» — «Выбрать» → для «claude»
   выбери ClaudeLauncher, потом повтори ссылку.
   → вперёд выходит окно «Теста» с новым чатом.
8. В «Тесте» начни сессию Code. На карточке «Теста» в лаунчере нажми на неё.
   → сессия открывается в окне «Теста»; то же для сессии стандартного профиля.
9. «+» → профиль «Вход» → открыть (без входа), остальные открыты.
   Войди в нём по почте: «Continue with email», ссылка из письма.
   → вход попадает во «Вход»; другие профили не показывают страницу с кодом.
   После — меню карточки «Вход» → «Убрать из списка».
10. Выйди из лаунчера (меню значка → «Выйти»). Снова открой claude://claude.ai/new.
   → открывается Claude, лаунчер сам не запускается.

D. Сессии
11. Открой лаунчер. Зажми строку сессии на карточке «Теста» и перетащи на карточку
    стандартного профиля → «Закрыть и скопировать» → сессия появилась в стандартном.
    В оповещении «Отменить» → копия исчезла.
12. «Возможности» → «Синхронизация сессий»: включи, отметь оба профиля. Закрой «Тест».
    → через пару секунд в «Тесте» есть сессии стандартного и наоборот (после его закрытия).

E. Kill Switch и значок
13. Настройки → Эксперименты → Kill Switch включи. Открой оба профиля.
    → оба работают; выключи VPN (если был) — оба теряют сеть, включи — сеть вернулась.
14. Включи «Скрыть значок Claude», перезапусти профили из лаунчера.
    → значков Claude в трее нет.

F. Выход из Windows
15. С открытым лаунчером выйди из сеанса Windows и войди снова.
    → уведомления Claude снова приходят от самого Claude, когда лаунчер не запущен.

Прислать: что не прошло (скриншоты), версию Claude (Справка → О программе)
и main.log Claude: %LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\Claude\logs\main.log
(нужны строки «boot: done» и «session ending … quitting the app»).
```

## Журнал

### 2026-10-03 — 1.6.4: Cowork
- Эксперимент на «Тесте»: Cowork в этой версии Claude — экран под «облачками» рядом с
  `</>`; сессии облачные. Задача с папкой из «Теста» выполнена основным Claude (тот же
  аккаунт держал подключение устройства), образ машины Cowork ≈ 9,5 ГБ скачан в
  `Claude/vm_bundles`. Журналы Claude общие для всех профилей.

### 2026-10-03 — 1.6.3: автосинхронизация (выпущена)
- Синхронизация в обе стороны: недостающее — из самого свежего, устаревшее заменяется
  (старая карточка — в журнал), удаления распространяются (нет, хотя было общим, или
  `deleted_`-маркер). Порог удалений: >5 и >20 % — стоп, остановленные остаются в
  общем состоянии, чтобы не «воскресли». Общее состояние — что реально есть у всех
  после прогона (иначе пропуски открытых профилей считались бы удалениями).
- Пишет только в закрытые профили; открытые — в `skipped`, догоняются при закрытии.

### 2026-10-03 — 1.6.0: раздельная память, проверка
- M-1…M-8 закоммичены (`154f3a8`), M-9 проверено автором на macOS.
- macOS `activate`: после активации — «открыть ещё раз» (`open -a` в обычном режиме,
  Apple Event `rapp` процессу в эксперименте), иначе закрытое окно Claude не возвращалось.
- `ClaudeCodeSessions.of` не отдаёт сессии в состоянии `unknown` (восстановленные из
  реестра после перезапуска) — они нужны только для привязки к профилю.

### 2026-10-03 — влита ветка parallelism
- Ветку проверили два агента-рецензента; найденное изменение обычного режима исправлено:
  без эксперимента хост и контроллер ведут себя как в 1.5.10 (см. roadmap, 1.7.0).
  Добавлены `NSAppleEventsUsageDescription`, проверка полной версии в CI, тесты обычного
  режима. Версия в `pubspec.yaml` — `1.5.10+31` (номера сборок тестовых сборок были до 30).
- Проверка Claude Desktop по коду (`app.asar`): переменная `CLAUDE_CONFIG_DIR` работает
  для вкладки Code — research, «Claude Code внутри Desktop».
