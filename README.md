# ClaudeLauncher

Несколько аккаунтов Claude на одном компьютере. ClaudeLauncher живёт в строке меню macOS
и в трее Windows и переключает приложение Claude между аккаунтами — рабочим, личным,
клиентским — в один клик, без выхода из аккаунта и без писем для входа.

**[Скачать последнюю версию](https://github.com/notcodeone/claude-launcher/releases/latest)** ·
[Что нового](CHANGELOG.md)

## Возможности

- **Профили Claude.** У каждого свой вход в аккаунт, настройки и история. Профиль
  «Основной» — ваш текущий вход в Claude, ничего переносить не нужно.
- **Переключение в один клик** — из строки меню, трея или окна лаунчера. Открытый Claude
  закрывается так же, как по Cmd+Q, и открывается выбранный профиль.
- **Лимиты открытого профиля** — кнопка с графиками слева от «Показать окно»:
  использованные проценты за 5 часов, неделю и другие доступные категории.
  Источник — последний снимок, сохранённый самим Claude.
- **Профиль по умолчанию** открывается вместе с лаунчером, а окно лаунчера остаётся над
  Claude, пока тот загружается.
- **Сессии Claude Code на карточке профиля:** работает, ждёт разрешения или ответа,
  готово — со временем и счётчиком токенов, как в самом Claude Code. Нажатие на название
  открывает сессию в Claude.
- **Уведомления Claude Code от лаунчера** — о запросе разрешения, вопросе и готовой
  задаче, без повторов от самого Claude. Нажатие открывает сессию.
- **Проверка страны:** где Claude недоступен, профиль не запускается, а лаунчер
  предупреждает об этом заранее.
- **Значок Claude можно спрятать** из строки меню или трея — переключаться удобнее
  через лаунчер.
- Светлая и тёмная тема или как в системе.

## Требования

- macOS 10.15 или новее (Apple Silicon и Intel) или Windows 10/11, 64-бит.
- Приложение Claude — [claude.com/download](https://claude.com/download).
- Для сессий и уведомлений — Claude Code, в терминале или в приложении Claude.

## Установка

Все файлы — на странице [последней версии](https://github.com/notcodeone/claude-launcher/releases/latest).

**macOS — `ClaudeLauncher-<версия>.dmg`.** Откройте образ и перетащите ClaudeLauncher
в «Программы».

Приложение пока не подписано Apple Developer ID, поэтому при первом запуске macOS
скажет, что не может его проверить. Нажмите «Готово», затем откройте «Системные
настройки» → «Конфиденциальность и безопасность» и нажмите «Всё равно открыть». Правый
клик → «Открыть» с macOS 15 больше не помогает. Можно и снять карантин в Терминале:

```bash
xattr -cr /Applications/ClaudeLauncher.app
```

Чтобы лаунчер запускался при входе: «Системные настройки» → «Основные» → «Объекты входа».

**Windows — `ClaudeLauncher-Setup-<версия>.exe`.** Ставит лаунчер для текущего
пользователя, без прав администратора, в `%LOCALAPPDATA%\Programs\ClaudeLauncher`.
Добавляет ярлык в «Пуск», по желанию — на рабочий стол и в автозапуск. SmartScreen
предупредит о неизвестном издателе: «Подробнее» → «Выполнить в любом случае».

**Windows без установки — `ClaudeLauncher-<версия>-windows-portable.zip`.** Распакуйте
папку целиком (рядом с `.exe` лежат нужные библиотеки) и запустите `claude_launcher.exe`.

**Обновление.** Выйдите из лаунчера через его меню и установите новую версию поверх
старой. Профили и настройки сохранятся.

## Начало работы

1. Запустите ClaudeLauncher. Откроется окно с приветствием и парой настроек. Сам
   лаунчер живёт в строке меню или трее — его значок такой же, как в шапке окна.
2. Профиль «Основной» уже есть — это ваш текущий вход в Claude.
3. Для другого аккаунта нажмите «Добавить» и назовите профиль. При первом запуске
   профиля войдите в аккаунт — дальше вход сохранится.
4. Переключайтесь из меню значка или из окна лаунчера.
5. Какой профиль открывать вместе с лаунчером, выберите в меню профиля «⋯» →
   «Открывать при запуске».

Окно можно закрыть — лаунчер продолжит работать. Выйти из него — «Выйти из
ClaudeLauncher» в меню значка.

## Как это работает

Приложение Claude хранит вход в аккаунт в своей папке данных. Если запустить его с флагом
`--user-data-dir=<папка>`, получится отдельный профиль со своим входом, настройками и
сессиями. Лаунчер держит список таких профилей и при переключении:

1. закрывает открытый Claude так же, как Cmd+Q. Принудительно — только по вашей кнопке,
   если Claude завис;
2. открывает Claude с папкой выбранного профиля.

Одновременно открыт только один профиль. Так ссылка входа из браузера всегда попадает в
нужный экземпляр, а виртуальные машины Cowork разных профилей не мешают друг другу.

Профиль по умолчанию открывается при запуске лаунчера, только если Claude ещё не открыт.
Claude, загружаясь, сам выходит на передний план, а лаунчер возвращает своё окно вперёд.
Как только вы сами переключитесь — кликом или клавишами, — лаунчер больше не вмешивается.

Удаление профиля из списка не трогает его папку данных — её можно удалить вручную.

## Сессии Claude Code

Если в настройках включены «События Claude Code», лаунчер добавляет свои HTTP-хуки в
`~/.claude/settings.json` и показывает на карточке открытого профиля его сессии:

- **Работает** — сколько идёт задача и сколько токенов Claude уже написал, как счётчик
  «↓ tokens» в самом Claude Code: каждый ответ модели по его `output_tokens`, вместе со
  скрытыми рассуждениями;
- **Ожидает** — оранжевым, если нужно разрешение, синим — если нужен ответ;
- **Готово** — время завершения; строка исчезает через час.

Время и токены обновляются раз в секунду, пока окно лаунчера открыто, а карточка
развёрнута. Токены растут ступеньками: лаунчер видит ответ модели, только когда тот
записан в переписку. Новое значение сменяет прежнее плавным затуханием.

Нажатие на название сессии открывает её в окне Claude. Сессии из терминала так не
открыть — для них просто выводится вперёд окно Claude. Нажатие на карточку сворачивает
сессии, и тогда последнее состояние видно цветной точкой на кнопке «Показать окно».

## Лимиты профиля

У открытого профиля слева от кнопки с глазом есть кнопка с графиками. Она показывает,
сколько процентов использовано в каждом доступном лимите: за 5 часов, за неделю, отдельно
для моделей и других категорий, которые Claude сохранил для этого профиля.

Это последний снимок из `plan-usage-history.json` в папке выбранного профиля. Лаунчер
не оценивает лимиты по токенам, не использует общий аккаунт Claude Code и не читает
данные входа или Связку ключей. История не содержит времени сброса лимитов —
на его месте стоит «—». Дата снимка и предупреждение об устаревании в меню
не выводятся.

Пока меню открыто, файл перечитывается раз в 30 секунд и по кнопке обновления. Это
не запрашивает свежие значения у сервера: сам Claude обновляет свою историю. Если
снимка ещё нет, проверьте «Настройки → Использование» в Claude.
На Windows учитывается также виртуализированная папка профиля MSIX.

Исследование будущих источников, включая существующую авторизацию Desktop на
macOS и Windows: [способы получения лимитов](docs/profile-usage-live-research.md).
Отдельно описана [постоянная подпись без аккаунтов разработчика](docs/application-signing.md).
Схема [однократного разрешения Keychain для всех профилей на Mac](docs/macos-profile-usage-keychain-access.md)
зафиксирована отдельно.
Эти варианты пока не включены в приложение.

## Уведомления

Пока лаунчер запущен, он сам сообщает, что Claude Code ждёт разрешения, ждёт ответа или
закончил задачу, а сами Claude в это время молчат. Нажатие на уведомление открывает
сессию в Claude. Выключается в настройках: «Уведомления через ClaudeLauncher».

- **Claude Code в терминале** перестаёт уведомлять сразу: лаунчер ставит
  `"preferredNotifChannel": "notifications_disabled"` в `~/.claude/settings.json`.
- **Приложение Claude** читает свои настройки уведомлений только при запуске. Поэтому
  лаунчер выключает их, пока профиль закрыт, а уже открытый Claude перестанет уведомлять
  сам после перезапуска.
- Пока вы смотрите в окно Claude, лаунчер о его сессиях не уведомляет — как и сам Claude.
- Если системные уведомления лаунчеру запрещены, уведомляет сам Claude.
- **Выход из лаунчера** возвращает всё как было: терминалу и закрытым Claude — сразу,
  открытым — как только их закроют. Если вы сами поменяли настройку, пока она была у
  лаунчера, остаётся ваш выбор.

## Проверка страны

Claude доступен не во всех странах. Перед запуском профиля лаунчер узнаёт страну по
IP-адресу и, если Claude там недоступен, профиль не запускает и показывает предупреждение.
Список стран — по [anthropic.com/supported-countries](https://www.anthropic.com/supported-countries).

- Проверка начинается с запуска лаунчера и повторяется перед каждым запуском профиля.
  Пока окно открыто, страна перепроверяется в фоне раз в 20 секунд.
- Где Claude недоступен, кнопки запуска неактивны. Уже открытый профиль лаунчер не
  закрывает.
- Если страну узнать не удалось (например, нет сети), вручную профиль запустить можно.
  Профиль по умолчанию при этом не открывается — лаунчер сообщит об этом.
- Кнопка с меткой в шапке показывает страну и проверяет её заново. Точка на ней:
  зелёная — Claude доступен, красная — нет, жёлтая — страну узнать не удалось.
- Выключается в настройках: «Проверять страну перед запуском».

## Конфиденциальность

- Лаунчер не собирает статистику и ничего не отправляет разработчикам.
- В интернет он обращается только для проверки страны — к публичным сервисам country.is,
  Cloudflare (`cdn-cgi/trace`), ipwho.is и ipapi.co. Им виден ваш IP-адрес. Проверку
  можно выключить.
- События Claude Code приходят к лаунчеру по HTTP внутри компьютера, на `127.0.0.1`.
- Чужие настройки лаунчер меняет только такие: хуки и канал уведомлений в
  `~/.claude/settings.json`, уведомления в `claude_desktop_config.json` профилей и
  видимость значка Claude. При выходе и удалении он возвращает их.

## Где хранятся данные

| | macOS | Windows |
|---|---|---|
| Стандартная папка Claude | `~/Library/Application Support/Claude` | папка пакета MSIX (как при запуске из «Пуск») |
| Папки профилей | `~/Library/Application Support/Claude-<имя>` | `%APPDATA%\Claude-<имя>` |
| Профили и настройки лаунчера | `~/Library/Application Support/com.notcodeone.claudeLauncher/` | `%APPDATA%\notcodeone\ClaudeLauncher\` |

## Удаление

- **macOS.** Выйдите из лаунчера через его меню и уберите его хуки и настройки:

  ```bash
  /Applications/ClaudeLauncher.app/Contents/MacOS/ClaudeLauncher --cleanup
  ```

  Затем перенесите ClaudeLauncher из «Программ» в Корзину.
- **Windows.** «Параметры» → «Приложения» → ClaudeLauncher → «Удалить». Хуки, значок и
  уведомления Claude удаление вернёт само.

Профили Claude и их данные удаление не трогает — папки `Claude-<имя>` можно удалить
вручную.

## Ограничения

- `--user-data-dir` — неофициальный способ; обновление Claude может его сломать.
- Переключение закрывает Claude — работа, которая в нём идёт, прервётся.
- **Windows:** при закрытии окна Claude уходит в трей, а не выходит, и попросить его выйти
  извне нельзя. Поэтому, если за 2 секунды Claude не вышел сам, лаунчер завершает его
  принудительно.
- **Windows:** на части компьютеров система не даёт запускать Claude из папки его пакета
  напрямую. Тогда лаунчер запускает профиль через пакет, как из «Пуска», и новые файлы
  профиля Windows может хранить в папке пакета: `%LOCALAPPDATA%\Packages\Claude_…\LocalCache\Roaming`.
- Приложение Claude читает настройки уведомлений только при запуске (см. «Уведомления»).

## Разработка

Flutter 3.44, Dart 3.12. Сборка для macOS — в Xcode 26 или новее: значок приложения
(`macos/Runner/AppIcon.icon`) — в формате Icon Composer.

```bash
flutter run -d macos          # или -d windows
flutter analyze
flutter test                  # юнит-тесты
flutter test integration_test/macos_host_test.dart -d macos   # на настоящем Claude
python3 tool/generate_icons.py   # перегенерировать все значки (macOS, нужен Pillow)
```

Интеграционный тест запускает отдельный тестовый профиль Claude во временной папке,
находит его, закрывает и удаляет папку. Уже открытый Claude не трогается.

Структура:

- `lib/src/claude/` — всё, что зависит от ОС: поиск Claude, список процессов, запуск, закрытие.
- `lib/src/launcher_controller.dart` — профили и логика переключения.
- `lib/src/integrations/` — события Claude Code, сессии на карточке и уведомления вместо
  самих Claude (`notification_handoff.dart`).
- `lib/src/location/` — проверка страны; список стран — `countries.dart`.
- `lib/src/tray.dart`, `lib/src/ui/` — меню в трее и окно лаунчера.
- `macos/Runner/MainFlutterWindow.swift` — закрытие и активация конкретного экземпляра
  Claude, окно лаунчера поверх остальных.

### Как устроено изнутри

- **Уведомления.** Как было до лаунчера, записано в `claude-notifications.json` рядом с
  профилями. После выхода в фоне остаётся наблюдатель — тот же ClaudeLauncher с флагом
  `--return-claude-notifications`, без окна и значка: он возвращает настройки открытым
  Claude, когда их закроют, и завершается. На macOS закрытия ждёт `/bin/sh`, а наблюдатель
  запускается только на возврат настроек — так Finder может заменить приложение новой
  версией. Если лаунчер завершился аварийно, уведомления вернутся при следующем выходе.
- **Сессии.** Название сессии берётся из её переписки, а открывается она по ссылке
  `claude://claude.ai/epitaxy/<id>`, которую выдаёт само приложение Claude (id сессии хук
  передаёт в заголовке). Если лаунчер перезапустили посреди задачи, её начало он находит
  в переписке.
- **Проверка страны.** Лаунчер спрашивает первый сервис, следующий — если предыдущие не
  ответили за 300 мс или ответили ошибкой. Ответ младше 30 секунд переиспользуется. Без
  сети профиль по умолчанию ждёт около 20 секунд. Украина в списке Anthropic есть, кроме
  нескольких областей, а по IP область не различить, так что лаунчер решает по стране.
- **Окно поверх Claude.** Пока профиль по умолчанию открывается, и ещё 20 секунд после,
  лаунчер раз в 250 мс проверяет, активно ли его окно. Если нет, а пользователь последнюю
  секунду ничего не нажимал, окно возвращается вперёд. На macOS время с последнего клика
  или клавиши — `CGEventSource`, на Windows — `GetLastInputInfo`, там в счёт идёт и
  движение мыши.

### Установщики

Собрать локально (после `flutter build …`):

```bash
tool/make_dmg.sh 1.1.2                                         # macOS
iscc /DAppVersion=1.2.0 windows\installer\claude_launcher.iss  # Windows, Inno Setup 6
```

Окно DMG (фон, размер, положение значков) берётся из шаблона `tool/dmg/template.dmg`.
`make_dmg.sh` только кладёт в него приложение, поэтому Finder для сборки не нужен, и она
работает в CI. Фон в macOS 26 должен задать сам Finder: записи `dmgbuild`, AppleScript и
ссылку на скрытый файл он не показывает. Поэтому шаблон готовится отдельно, с одним
ручным шагом в Finder:

```bash
python3 tool/generate_dmg_background.py   # фон: tool/dmg/background.tiff (нужен Pillow)
tool/make_dmg_template.sh                 # шаблон: tool/dmg/template.dmg
```

Сборки каждого коммита собирает GitHub Actions: вкладка **Actions** → запуск **Build** →
артефакты.

### Версии

Номер версии — в `pubspec.yaml`: MAJOR.MINOR.PATCH и номер сборки после `+`. Из него
берутся версия приложения в macOS и Windows, имена установщиков и номер в подвале окна.
Что изменилось в каждой версии — в [CHANGELOG.md](CHANGELOG.md).

Как выпустить версию:

1. Поднять номер в `pubspec.yaml`: для исправлений — PATCH, для нового — MINOR, для
   несовместимых изменений — MAJOR. Номер сборки каждый раз увеличивать на 1.
2. Добавить в `CHANGELOG.md` раздел `## X.Y.Z — дата` с тем, что изменилось.
3. Закоммитить, поставить тег и запушить его: `git tag vX.Y.Z && git push origin main vX.Y.Z`.

По тегу GitHub Actions собирает установщики и публикует выпуск «ClaudeLauncher X.Y.Z» с
текстом из раздела версии в `CHANGELOG.md` (`tool/release_notes.sh`). Если тег не
совпадает с версией в `pubspec.yaml` или раздела нет, выпуск не публикуется.
