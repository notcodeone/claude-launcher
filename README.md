# ClaudeLauncher

Лаунчер в строке меню macOS и в трее Windows. Переключает приложение Claude между
аккаунтами (например, рабочим и личным) без выхода из аккаунта и без писем для входа.

## Как это работает

Приложение Claude хранит вход в аккаунт в своей папке данных. Если запустить его с флагом
`--user-data-dir=<папка>`, получится отдельный профиль со своим входом, настройками
и сессиями. Лаунчер держит список таких профилей и переключает их в один клик:

1. корректно закрывает открытый Claude (как Cmd+Q; принудительно — никогда);
2. открывает Claude с папкой выбранного профиля.

Одновременно запущен только один профиль. Так ссылка входа из браузера всегда попадает
в нужный экземпляр, и виртуальные машины Cowork разных профилей не конфликтуют.

Профиль «Основной» использует стандартную папку Claude — это ваш текущий вход.
Для каждого нового профиля один раз нужно войти в аккаунт, дальше вход сохраняется.

Профиль с тегом «По умолчанию» лаунчер открывает при своём запуске, если Claude ещё
не запущен. Сначала это «Основной»; поменять — в меню профиля «⋯» → «Открывать при запуске».

| | macOS | Windows |
|---|---|---|
| Стандартная папка | `~/Library/Application Support/Claude` | папка пакета MSIX (как при запуске из «Пуск») |
| Папки профилей | `~/Library/Application Support/Claude-<имя>` | `%APPDATA%\Claude-<имя>` |
| Список профилей | `~/Library/Application Support/com.notcodeone.claudeLauncher/profiles.json` | `%APPDATA%\notcodeone\ClaudeLauncher\profiles.json` |
| Уведомления Claude до лаунчера | там же, `claude-notifications.json` | там же, `claude-notifications.json` |

Удаление профиля из списка не трогает его папку данных — её можно удалить вручную.

## Сессии Claude Code

Если в настройках включены события Claude Code, лаунчер добавляет свои HTTP-хуки
в `~/.claude/settings.json` и показывает на карточке запущенного профиля его сессии:

- **Работает** — сколько времени идёт задача и сколько токенов Claude уже написал —
  так же, как счётчик «↓ tokens» в самом Claude Code. Каждый ответ модели считается
  по его `output_tokens`, вместе со скрытыми рассуждениями. Если их нет — по длине
  ответа;
- **Ожидает** — оранжевым, если нужно разрешение, синим — если нужен ответ;
- **Готово** — время завершения; строка исчезает через час.

Время и токены обновляются раз в секунду, но только пока окно лаунчера открыто, а карточка
развёрнута; иначе переписку лаунчер не читает вовсе и догоняет при открытии. Токены
растут ступеньками: Claude Code растит своё число по ходу печати, а лаунчер видит
ответ, только когда тот записан в переписку. Длинное рассуждение или большой файл
появляются целиком, поэтому новое значение плавно добегает примерно за секунду. Если лаунчер
перезапустили посреди задачи, её начало он находит в переписке.

Название сессии берётся из её переписки. Нажатие на него открывает эту сессию в окне
Claude — по ссылке `claude://claude.ai/epitaxy/<id>`, которую выдаёт само приложение
Claude (id сессии хук передаёт в заголовке). Сессии из терминала так не открыть — для них
просто выводится вперёд окно Claude. Нажатие на карточку сворачивает сессии — тогда
последнее состояние видно цветной точкой на кнопке «Показать окно».

## Уведомления

Пока лаунчер запущен, он сам сообщает, что Claude Code ждёт разрешения, ждёт ответа или
закончил задачу, а сами Claude молчат. Нажатие на уведомление открывает сессию в Claude. Выключается в настройках:
«Уведомления через ClaudeLauncher» (есть, только когда включены события Claude Code).
Если системные уведомления лаунчеру запрещены, уведомляет сам Claude.

- **Claude Code в терминале.** Лаунчер ставит `"preferredNotifChannel":
  "notifications_disabled"` в `~/.claude/settings.json`. Claude Code читает эту настройку
  при каждом уведомлении, поэтому она действует сразу. Лаунчер уведомляет так же, как сам
  Claude Code: о разрешении и о том, что тот давно ждёт ввода.
- **Приложение Claude.** Лаунчер выключает `preferences.notificationLevels` в
  `claude_desktop_config.json` папки профиля. Claude читает этот файл один раз при запуске,
  держит в памяти и переписывает целиком. Поэтому лаунчер меняет файл, только пока Claude этого
  профиля закрыт: перед запуском и после закрытия. Уже открытый Claude перестанет
  уведомлять сам после перезапуска. Пока вы смотрите в окно Claude, лаунчер о его
  сессиях не уведомляет — как и сам Claude.
- **Как было до лаунчера**, записано в `claude-notifications.json`. Если вы сами поменяли
  настройку, пока она была у лаунчера, остаётся ваш выбор.
- **Выход из лаунчера** возвращает уведомления: терминалу и закрытым Claude — сразу,
  открытым — как только их закроют. Для этого в фоне остаётся наблюдатель: тот же
  ClaudeLauncher с флагом `--return-claude-notifications`, без окна и значка. Закончив, он
  завершается сам. Если снова запустить лаунчер, настройки забирает лаунчер. На macOS
  закрытия Claude ждёт оболочка `/bin/sh`, а наблюдатель запускается только чтобы вернуть
  настройки. Так он не держит приложение, и Finder может заменить его новой версией.
- Если лаунчер завершился аварийно, уведомления Claude вернутся при следующем выходе из
  него. На Windows их возвращает и удаление. На macOS перед удалением выйдите из лаунчера
  через его меню.

## Проверка страны

Claude доступен не во всех странах. Перед запуском профиля лаунчер узнаёт страну по
IP-адресу и, если Claude там недоступен, профиль не запускает и показывает
предупреждение. Список стран — `lib/src/location/countries.dart`, по
[anthropic.com/supported-countries](https://www.anthropic.com/supported-countries):
списки для Claude.ai и API там совпадают. Украина в нём есть, кроме нескольких областей,
а по IP область не различить, так что лаунчер решает по стране.

- Страну называют публичные сервисы без ключей: country.is, Cloudflare (`cdn-cgi/trace`),
  ipwho.is и ipapi.co. Лаунчер спрашивает первый. Следующий он спрашивает, если
  предыдущие не ответили за 300 мс или ответили ошибкой. Им виден ваш IP-адрес.
- Проверка начинается с самого запуска лаунчера, до профиля по умолчанию. Окно
  лаунчера при запуске открывается сразу и показывает загрузку: проверку страны и
  открытие профиля. Проверка повторяется и перед каждым запуском профиля, но ответ
  младше 30 секунд переиспользуется.
- Где Claude недоступен, кнопки запуска в карточках и в меню трея неактивны, а в окне
  красная плашка. Уже открытый профиль можно показать, лаунчер его не закрывает. Пока
  окно открыто, страна перепроверяется в фоне раз в 20 секунд. Когда сеть сменится,
  кнопки станут активны сами.
- Если страну узнать не удалось (нет сети), вручную профиль запустить можно. Профиль по
  умолчанию при старте лаунчера не открывается: лаунчер ждёт сеть около 20 секунд, а
  потом сообщает, что не открыл его.
- Кнопка с меткой в шапке показывает страну и проверяет её заново. Цвет точки на ней:
  зелёный — Claude доступен, красный — нет, жёлтый — страну узнать не удалось.
  Выключается в настройках: «Проверять страну перед запуском».

## Установка

Готовые версии — на странице **Releases** репозитория: DMG для macOS, установщик и
переносная версия для Windows. Сборки между версиями собирает GitHub Actions: вкладка
**Actions** → последний запуск **Build** → артефакты.

- **macOS — `ClaudeLauncher-<версия>.dmg`:** откройте образ и перетащите
  «ClaudeLauncher» в «Программы». Сборка не подписана Apple Developer ID, поэтому
  при первом запуске macOS скажет, что не может проверить приложение. Нажмите «Готово»,
  затем «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно
  открыть» (правый клик → «Открыть» с macOS 15 больше не помогает). Или снимите
  карантин: `xattr -cr "/Applications/ClaudeLauncher.app"`.
  Чтобы лаунчер запускался при входе: «Системные настройки» → «Основные» → «Объекты входа».
- **Windows — `ClaudeLauncher-Setup-<версия>.exe`:** ставит для текущего пользователя,
  без прав администратора, в `%LOCALAPPDATA%\Programs\ClaudeLauncher`. Добавляет ярлык
  в «Пуск», по желанию — на рабочий стол и автозапуск при входе. SmartScreen предупредит
  о неизвестном издателе: «Подробнее» → «Выполнить в любом случае». Удаление — через
  «Параметры» → «Приложения»; оно убирает хуки лаунчера из `~/.claude/settings.json`,
  возвращает значок Claude в трей и его уведомления, профили Claude и их данные не трогает.
- **Windows без установки — `ClaudeLauncher-windows-portable`:** распакуйте папку
  целиком (рядом с `.exe` лежат нужные DLL) и запустите `claude_launcher.exe`.

Собрать установщики локально (после `flutter build …`):

```bash
tool/make_dmg.sh 1.0.0                                      # macOS
iscc /DAppVersion=1.0.0 windows\installer\claude_launcher.iss  # Windows, Inno Setup 6
```

Окно DMG (фон, размер, положение значков) берётся из шаблона `tool/dmg/template.dmg`.
`make_dmg.sh` только кладёт в него приложение, поэтому Finder для сборки не нужен, и она
работает в CI. Фон в macOS 26 должен задать сам Finder: записи `dmgbuild`, AppleScript и
ссылку на скрытый файл он не показывает. Поэтому шаблон готовится отдельно, с одним
ручным шагом в Finder:

```bash
python3 tool/generate_dmg_background.py   # фон: tool/dmg/background.tiff (нужен Pillow)
tool/make_dmg_template.sh                 # шаблон: tool/dmg/template.dmg
```

## Ограничения

- `--user-data-dir` — неофициальный способ; обновление Claude может его сломать.
- **Windows:** при закрытии окна Claude уходит в трей, а не выходит, — попросить его выйти
  извне нельзя. Поэтому, если за 2 секунды Claude не вышел сам, лаунчер завершает его
  принудительно (при переключении и «Завершить работу»). На macOS Claude выходит как по
  Cmd+Q, а принудительно — только по кнопке, если он завис.
- Переключение закрывает Claude — работа, которая в нём идёт, прервётся.
- Уведомления приложения Claude лаунчер выключает и возвращает через его файл настроек,
  а Claude читает этот файл только при запуске (см. «Уведомления»).

## Версии

Номер версии — в `pubspec.yaml`: `version: 1.1.0+2`, то есть MAJOR.MINOR.PATCH и номер
сборки после `+`. Из него берутся версия приложения в macOS и Windows, имена установщиков и
номер в подвале окна. Что изменилось в каждой версии — в [CHANGELOG.md](CHANGELOG.md).

Как выпустить версию:

1. Поднять номер в `pubspec.yaml`: для исправлений — PATCH, для нового — MINOR, для
   несовместимых изменений — MAJOR. Номер сборки каждый раз увеличивать на 1.
2. Добавить в `CHANGELOG.md` раздел `## X.Y.Z — дата` с тем, что изменилось.
3. Закоммитить, поставить тег и запушить его: `git tag vX.Y.Z && git push origin main vX.Y.Z`.

По тегу GitHub Actions собирает установщики и публикует выпуск «ClaudeLauncher X.Y.Z»:
DMG, установщик и переносную версию для Windows, с текстом из раздела версии в
`CHANGELOG.md`. Если тег не совпадает с версией в `pubspec.yaml` или раздела нет, выпуск не
публикуется.

## Разработка

Flutter 3.44, Dart 3.12. Сборка для macOS — в Xcode 26 или новее: значок приложения
(`macos/Runner/AppIcon.icon`) — в формате Icon Composer.

```bash
flutter run -d macos          # или -d windows
flutter analyze
flutter test                  # юнит-тесты
flutter test integration_test/macos_host_test.dart -d macos   # на настоящем Claude
python3 tool/generate_icons.py   # перегенерировать все значки (macOS, нужен Pillow)
```

Интеграционный тест запускает отдельный тестовый профиль Claude во временной папке,
находит его, закрывает и удаляет папку. Уже открытый Claude не трогается.

Структура:

- `lib/src/claude/` — всё, что зависит от ОС: поиск Claude, список процессов, запуск, закрытие.
- `lib/src/launcher_controller.dart` — профили и логика переключения.
- `lib/src/integrations/` — события Claude Code, сессии на карточке и уведомления вместо
  самих Claude (`notification_handoff.dart`).
- `lib/src/tray.dart`, `lib/src/ui/` — меню в трее и окно настроек.
- `macos/Runner/MainFlutterWindow.swift` — закрытие и активация конкретного экземпляра Claude.
