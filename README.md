# ClaudeLauncher

Несколько аккаунтов Claude на одном компьютере. ClaudeLauncher живёт в строке меню macOS
и в трее Windows и переключает приложение Claude между аккаунтами — рабочим, личным,
клиентским — в один клик, без выхода из аккаунта и без писем для входа.

**[Скачать последнюю версию](https://github.com/notcodeone/claude-launcher/releases/latest)** ·
[Что нового](CHANGELOG.md)

## Возможности

- **Профили Claude.** У каждого свой вход в аккаунт, настройки и история. Профиль
  «Основной» — ваш текущий вход в Claude, ничего переносить не нужно.
- **Переключение в один клик** — из строки меню, трея или окна лаунчера. Открытый Claude
  закрывается так же, как по Cmd+Q, и открывается выбранный профиль.
- **Лимиты открытого профиля** (экспериментальная функция) — кнопка с графиками слева
  от «Показать окно»: сколько использовано за 5 часов, за неделю и по моделям и когда
  лимит сбросится. Из данных, которые сохраняет сам Claude, — без входа и паролей.
- **Профиль по умолчанию** открывается вместе с лаунчером, а окно лаунчера остаётся над
  Claude, пока тот загружается.
- **Обновления из самого лаунчера** — одной кнопкой, без DMG и предупреждений системы.
- **Сессии Claude Code на карточке профиля:** работает, ждёт разрешения или ответа,
  готово — со временем и счётчиком токенов, как в самом Claude Code. Нажатие на название
  открывает сессию в Claude.
- **Уведомления Claude Code от лаунчера** — о запросе разрешения, вопросе и готовой
  задаче, без повторов от самого Claude. Нажатие открывает сессию.
- **Проверка страны:** где Claude недоступен, профиль не запускается, а лаунчер
  предупреждает об этом заранее.
- **Kill Switch** (экспериментальная функция): отключился VPN — соединения Claude с
  Anthropic рвутся мгновенно, сменилась страна — Claude закрывается. Защищает и Claude
  Code, и машину Cowork.
- **Значок Claude можно спрятать** из строки меню или трея — переключаться удобнее
  через лаунчер. Лаунчер включает для этого собственную настройку Claude
  (`menuBarEnabled`), поэтому значок пропадает совсем — со следующего запуска Claude.
- **Параллельные профили** (экспериментальная функция, в разработке): несколько профилей
  открыты одновременно. Входить в аккаунт пока лучше при одном открытом профиле; Cowork и
  Windows ещё проверяются. Подробности — [docs/parallel-profiles.md](docs/parallel-profiles.md).
- Светлая и тёмная тема или как в системе.

## Требования

- macOS 10.15 или новее (Apple Silicon и Intel) или Windows 10/11, 64-бит.
- Приложение Claude — [claude.com/download](https://claude.com/download).
- Для сессий и уведомлений — Claude Code, в терминале или в приложении Claude.

## Установка

**Проще всего — одной командой.** Она скачивает последнюю версию, ставит её и запускает.
Так система не показывает предупреждение о неизвестном разработчике: оно появляется только
у файлов, скачанных браузером. Этой же командой можно обновиться.

macOS, в Терминале:

```bash
curl -fsSL https://raw.githubusercontent.com/notcodeone/claude-launcher/main/tool/install.sh | bash
```

Windows, в PowerShell:

```powershell
irm https://raw.githubusercontent.com/notcodeone/claude-launcher/main/tool/install.ps1 | iex
```

**Вручную** — файлы на странице [последней версии](https://github.com/notcodeone/claude-launcher/releases/latest).

- **macOS — `ClaudeLauncher-<версия>.dmg`.** Откройте образ и перетащите ClaudeLauncher
  в «Программы». Приложение не подписано Apple Developer ID, поэтому при первом запуске
  macOS скажет, что не может его проверить. Нажмите «Готово», затем «Системные
  настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть» (правый клик →
  «Открыть» с macOS 15 больше не помогает). Или снимите пометку в Терминале:
  `xattr -cr /Applications/ClaudeLauncher.app`.
- **Windows — `ClaudeLauncher-Setup-<версия>.exe`.** Ставит лаунчер для текущего
  пользователя, без прав администратора, в `%LOCALAPPDATA%\Programs\ClaudeLauncher`.
  Добавляет ярлык в «Пуск», по желанию — на рабочий стол и в автозапуск. SmartScreen
  предупредит о неизвестном издателе: «Подробнее» → «Выполнить в любом случае».
- **Windows без установки — `ClaudeLauncher-<версия>-windows-portable.zip`.** Распакуйте
  папку целиком (рядом с `.exe` лежат нужные библиотеки) и запустите `claude_launcher.exe`.

Чтобы лаунчер запускался при входе в macOS: «Системные настройки» → «Основные» →
«Объекты входа». Значок лаунчера в Dock включается в его настройках: «Основные» → «Значок в Dock».
Выход из Dock или ⌘Q работает так же, как «Выйти из ClaudeLauncher» в меню значка.

### Обновление

Лаунчер сам проверяет обновления — через 15 секунд после запуска, раз в 6 часов и при
открытии окна, если с прошлой проверки прошло больше 10 минут. Проверить сразу — пункт
«Проверить обновления» в меню значка. Когда выходит новая версия, в подвале окна и в меню
значка появляется «Обновить до X». По нажатию лаунчер
скачивает её, сверяет с контрольной суммой из выпуска, ставит вместо себя и
перезапускается; ход виден в шапке окна. Профили и настройки сохраняются,
предупреждений системы нет: файл скачивает сам лаунчер, а не браузер.

- **macOS** — так обновляется приложение, лежащее в папке, куда можно писать (обычно
  «Программы»). Запущенное с образа или из папки сборки — открывает страницу выпуска.
- **Windows** — так обновляется установленная версия: лаунчер тихо запускает новый
  установщик, тот дожидается выхода лаунчера и запускает новую версию. Если установка не
  удалась, запускается прежняя, а журнал — в `%TEMP%\ClaudeLauncher-update.log`.
  Переносная версия открывает страницу выпуска.

Там же, в «Настройки» → «Обновления», — версия, «Проверить сейчас» и «Что нового»;
автоматическую проверку можно выключить. Если GitHub не ответил
(нет сети или без входа он отвечает не больше 60 раз в час с одного адреса), лаунчер
повторит проверку через 5 минут.

## Начало работы

1. Запустите ClaudeLauncher. Откроется окно с приветствием и парой настроек. Сам
   лаунчер живёт в строке меню или трее — его значок такой же, как в шапке окна.
2. Профиль «Основной» уже есть — это ваш текущий вход в Claude.
3. Для другого аккаунта нажмите «Добавить» и назовите профиль. При первом запуске
   профиля войдите в аккаунт — дальше вход сохранится.
4. Переключайтесь из меню значка или из окна лаунчера.
5. Какой профиль открывать вместе с лаунчером, выберите в меню профиля «⋯» →
   «Открывать при запуске».

Настройки — шестерёнка в шапке окна или ⌘, (Ctrl+, на Windows): разделы «Основные»
(проверка страны, значок в Dock, тема), «Claude Code» (сессии, уведомления, значок Claude),
«Обновления» и «Эксперименты». Назад — стрелка в шапке или Esc.

Окно можно закрыть — лаунчер продолжит работать. Выйти из него — «Выйти из
ClaudeLauncher» в меню значка.

## Как это работает

Приложение Claude хранит вход в аккаунт в своей папке данных. Если запустить его с флагом
`--user-data-dir=<папка>`, получится отдельный профиль со своим входом, настройками и
сессиями. Лаунчер держит список таких профилей и при переключении:

1. закрывает открытый Claude так же, как Cmd+Q. Принудительно — только по вашей кнопке,
   если Claude завис;
2. открывает Claude с папкой выбранного профиля.

В обычном режиме одновременно открыт только один профиль. Так ссылка входа из браузера всегда попадает в
нужный экземпляр, а виртуальные машины Cowork разных профилей не мешают друг другу.

Профиль по умолчанию открывается при запуске лаунчера, только если Claude ещё не открыт.
Claude, загружаясь, сам выходит на передний план, а лаунчер возвращает своё окно вперёд.
Как только вы сами переключитесь — кликом или клавишами, — лаунчер больше не вмешивается.

Удаление профиля из списка не трогает его папку данных — её можно удалить вручную.

## Сессии Claude Code

Если в настройках («Claude Code») включены «События Claude Code», лаунчер добавляет свои HTTP-хуки в
`~/.claude/settings.json` (и в папку Claude Code каждого профиля со своей памятью) и
показывает на карточке открытого профиля сессии вкладки Code. Claude Code в терминале
лаунчер не показывает — только приложение Claude.

- **Работает** — сколько идёт задача и сколько токенов Claude уже написал, как счётчик
  «↓ tokens» в самом Claude Code: каждый ответ модели по его `output_tokens`, вместе со
  скрытыми рассуждениями;
- **Ожидает** — оранжевым, если нужно разрешение, синим — если нужен ответ;
- **Готово** — время завершения; строка исчезает через час.

Время и токены обновляются раз в секунду, пока окно лаунчера открыто, а карточка
развёрнута. Токены растут ступеньками: лаунчер видит ответ модели, только когда тот
записан в переписку. Новое значение сменяет прежнее плавным затуханием.

Нажатие на название сессии открывает её в окне Claude. Нажатие на карточку сворачивает
сессии, и тогда последнее состояние видно цветной точкой на кнопке «Показать окно».

## Лимиты профиля

Экспериментальная функция: включается в «Настройки» → «Эксперименты» → «Лимиты профиля».
При первом входе в «Эксперименты» лаунчер предупреждает, что такие функции ещё
проверяются и пользоваться ими — на свой страх и риск.
Там же, каждая со своим переключателем, будут появляться другие функции, которые ещё
проверяются.

У открытого профиля слева от кнопки с глазом есть кнопка с графиками. Она показывает,
сколько процентов использовано за 5 часов, за неделю и отдельно по моделям, и когда
лимит сбросится: «Сброс через 2 ч 10 мин», «Сброс в вс, 21:00». Пятичасовое окно, которое
ещё не началось, помечено «Начнётся с первого запроса».

Лаунчер берёт данные из папки профиля — то, что сохраняет сам Claude. Он не входит в
аккаунт, не читает пароли, cookies, токены и Связку ключей и не обращается к серверу:

- **ответ сервера в HTTP-кэше Claude** (`Cache/Cache_Data`) — проценты, точное время
  сброса и все категории, как в «Настройки → Использование». Он обновляется, когда
  Claude сам запрашивает лимиты;
- **`plan-usage-history.json`** — проценты, которые Claude записывает раз в 15 минут,
  пока открыт.

Сам Claude запрашивает лимиты, пока открыт, — примерно раз в 15–20 минут, поэтому цифры
в окне отстают от сервера в среднем на 10–20 минут. Если пятичасовое окно сбросилось, а
свежего ответа ещё нет, вместо процента нового окна видно «Сброшен в 15:10».

Проценты берутся из того, что новее. Недельный лимит сбрасывается каждые 7 дней в одно
и то же время, поэтому его сброс известен и по старому ответу. Пятичасовой — точно, пока
действует окно из ответа сервера, иначе примерно, по истории («Сброс примерно через…»);
если по истории не понять, время не показывается. Пока меню открыто, данные
перечитываются раз в 30 секунд и по «Проверить снова». На Windows учитывается и
виртуализированная папка профиля MSIX; кэш там пока не проверен.

Исследование других источников: [способы получения лимитов](docs/profile-usage-live-research.md),
[постоянная подпись без аккаунтов разработчика](docs/application-signing.md),
[однократное разрешение Keychain на Mac](docs/macos-profile-usage-keychain-access.md).

## Уведомления

Пока лаунчер запущен, он сам сообщает, что Claude Code ждёт разрешения, ждёт ответа или
закончил задачу, а сами Claude в это время молчат. Нажатие на уведомление открывает
сессию в Claude. Выключается в «Настройки» → «Claude Code»: «Уведомления через ClaudeLauncher».

- **Claude Code в терминале** перестаёт уведомлять сразу: лаунчер ставит
  `"preferredNotifChannel": "notifications_disabled"` в `~/.claude/settings.json`.
- **Приложение Claude** читает свои настройки уведомлений только при запуске. Поэтому
  лаунчер выключает их, пока профиль закрыт, а уже открытый Claude перестанет уведомлять
  сам после перезапуска.
- Пока вы смотрите в окно Claude, лаунчер о его сессиях не уведомляет — как и сам Claude.
- Если системные уведомления лаунчеру запрещены, уведомляет сам Claude.
- **Выход из лаунчера** возвращает всё как было: терминалу и закрытым Claude — сразу,
  открытым — как только их закроют. Если вы сами поменяли настройку, пока она была у
  лаунчера, остаётся ваш выбор.

## Проверка страны

Claude доступен не во всех странах. Перед запуском профиля лаунчер узнаёт страну по
IP-адресу и, если Claude там недоступен, профиль не запускает и показывает предупреждение.
Список стран — по [anthropic.com/supported-countries](https://www.anthropic.com/supported-countries).

- Проверка начинается с запуска лаунчера и повторяется перед каждым запуском профиля.
  Пока окно открыто, страна перепроверяется в фоне раз в 20 секунд.
- Где Claude недоступен, кнопки запуска неактивны. Уже открытый профиль лаунчер не
  закрывает.
- Если страну узнать не удалось (например, нет сети), вручную профиль запустить можно.
  Профиль по умолчанию при этом не открывается — лаунчер сообщит об этом.
- Кнопка с меткой в шапке показывает страну и проверяет её заново. Точка на ней:
  зелёная — Claude доступен, красная — нет, жёлтая — страну узнать не удалось.
- Выключается в «Настройки» → «Основные»: «Проверять страну перед запуском».

## Kill Switch

Экспериментальная функция: «Настройки» → «Эксперименты» → «Kill Switch». Нужна тем, кто
открывает Claude через VPN: если VPN отключился или сменилась страна, к Anthropic не
должно уйти ни одного запроса. Пока функция включена, в шапке окна — кнопка со щитом. Точка
на ней — состояние: зелёная — сеть проверена, жёлтая — проверяется или нужно перезапустить
Claude, красная — Kill Switch сработал. В её окне — подробности, «Проверить сеть» и
переход к настройкам.

- **Весь трафик Claude идёт через лаунчер.** Лаунчер прописывает Claude свой прокси —
  официальной настройкой Claude `egressProxyUrl`. Через него идут само приложение,
  Claude Code, который оно запускает, и машина Cowork. Прокси работает только на
  `127.0.0.1` и трафик не расшифровывает: лишь пропускает или нет.
- **Затвор.** Прокси пропускает соединения, только пока сеть та же, при которой проверена
  страна. Сменилась сеть — открытые соединения рвутся мгновенно, а новые ждут, пока
  лаунчер проверит страну (обычно меньше секунды), — не получают отказ, поэтому Claude не
  застревает на экране «нет сети». Та же страна (например, VPN переподключился) — они
  идут дальше. Другая или Claude там недоступен — получают отказ, а Claude закрывается
  сразу, без сохранения, вместе со своим Claude Code.
- О смене сети лаунчер узнаёт сразу — от системы (`NWPathMonitor` на macOS,
  `NotifyUnicastIpAddressChange` на Windows), а ещё раз в 250 мс сверяет адреса и перед
  каждым новым соединением — сеть. Раз в 30 секунд, пока открыт Claude, проверяет страну
  по IP: VPN может сменить сервер, не меняя адресов.
- **Отказ — в закрытую сторону.** Если прокси недоступен, Claude не идёт в обход, а
  остаётся без сети. Поэтому Claude не запускается, пока затвор не поднят, а если Kill
  switch выключили при открытом Claude, затвор пропускает его трафик без проверок, пока
  Claude не закроют, — и только потом снимает настройку.
- **После выхода из лаунчера** (через меню или Cmd+Q), пока Claude открыт, защиту держит
  фоновый процесс лаунчера — без окна и значка. Claude закрылся — процесс снимает
  настройку и завершается; лаунчер запустили снова — передаёт ему работу. Если этот
  процесс закрыли (например, `quit app "ClaudeLauncher"` или команда установки), он тоже
  снимает настройку — следующий запуск Claude пойдёт напрямую, — а лаунчер, запущенный
  следом, поднимает затвор для ещё открытого Claude. Если лаунчер или этот процесс
  завершили принудительно, Claude останется без сети, пока лаунчер не запустят снова.
- Защищён Claude, открытый после включения функции, — лаунчером или из Dock: настройку
  Claude читает при запуске. Если Claude был открыт раньше, лаунчер предложит
  перезапустить его, а до тех пор закроет Claude при смене страны.
- **Закрывать Claude при любой смене сети** (по умолчанию выключено) — вдобавок к затвору
  закрывать Claude сразу, не дожидаясь проверки страны. Закроется и при безобидной смене
  Wi-Fi.
- **Обновления Claude ставит лаунчер.** Встроенное обновление Claude не слушает прокси и
  ходило бы к Anthropic напрямую, поэтому, пока Kill Switch включён, оно выключено
  (`disableAutoUpdates`). Вместо него лаунчер сам спрашивает ленту обновлений Claude — со
  случайным `device_id` и только через проверенную сеть — и предлагает обновить. Архив он
  проверяет (контрольная сумма из ленты, подпись того же разработчика, что у
  установленного Claude; на Windows пакет MSIX проверяет сама система), закрывает Claude,
  ставит новую версию и открывает Claude снова. Сменилась сеть во время загрузки —
  загрузка прерывается.
- Не защищены claude.ai в браузере и Claude Code, установленный отдельно от приложения
  Claude. Их прикрывает Kill Switch самого VPN-клиента — лучше включить оба.
- Настройка лежит в папке `<папка профиля>-3p`. На Windows папка одна на все профили —
  `%LOCALAPPDATA%\Claude-3p`: Claude из пакета MSIX читает её напрямую, без
  виртуализации. Если там уже есть чужая конфигурация — её мог настроить администратор, — лаунчер её не трогает и профиль
  не запускает: без прокси Claude пошёл бы напрямую. Чтобы открыть его без защиты,
  выключите Kill Switch.
- Смена сети — это смена адресов на адаптерах, кроме адаптеров виртуальных машин
  (`bridge100` на macOS, `vEthernet (Default Switch)` и `vEthernet (WSL)` на Windows):
  запуск машины Cowork или WSL затвор не трогает.
- **Windows:** установщик, запущенный, пока Claude открыт через Kill Switch, закрывает
  фоновый процесс лаунчера и сразу запускает новую версию — она поднимает затвор.
- **Windows: «Cowork — только через Kill Switch».** Машина Cowork работает в службе
  Windows (`CoworkVMService`, от имени системы) — Kill Switch её не закрывает. Её трафик
  и так идёт через прокси лаунчера, а этот переключатель — страховка: правило
  брандмауэра не выпускает службу в интернет мимо затвора (соединения внутри компьютера
  брандмауэр не фильтрует). Правило — по имени службы и переживает обновления Claude.
  Ставить и снимать его Windows разрешает только администратору — она спросит
  разрешение. Выключили Kill Switch — правило снимается, иначе Cowork остался бы без сети.
- **Windows: выход из сеанса и выключение.** Лаунчер успевает корректно выйти —
  вернуть Claude уведомления. Kill Switch при этом остаётся закреплённым: после входа
  Claude не пойдёт мимо затвора, а затвор поднимется вместе с лаунчером.

## Конфиденциальность

- Лаунчер не собирает статистику и ничего не отправляет разработчикам.
- В интернет он обращается только для проверки страны — к публичным сервисам country.is,
  Cloudflare (`cdn-cgi/trace`), ipwho.is и ipapi.co — и для проверки обновлений — к
  GitHub (`api.github.com`, а при обновлении — к файлам выпуска). Им виден ваш IP-адрес.
  Обе проверки можно выключить. Kill Switch, пока открыт Claude, проверяет страну у тех
  же сервисов раз в 30 секунд и при каждой смене сети.
- Прокси Kill Switch работает только внутри компьютера, на `127.0.0.1`. Он не
  расшифровывает трафик Claude и ничего из него не сохраняет — лишь пропускает
  соединение или нет.
- События Claude Code приходят к лаунчеру по HTTP внутри компьютера, на `127.0.0.1`.
- Чужие настройки лаунчер меняет только такие: хуки и канал уведомлений в
  `~/.claude/settings.json`, уведомления и значок Claude (`menuBarEnabled`) в
  `claude_desktop_config.json` профилей, видимость значка в системе, а с Kill Switch — `egressProxyUrl` в папках `…-3p`. При
  выходе и удалении он возвращает их.

## Своя память Claude Code

Вкладка Code в Claude хранит память проектов, переписку, историю и разрешения в папке
Claude Code — обычно `~/.claude`, одной на все профили. Тогда то, что Claude запомнил в
рабочем профиле, видно и в личном. Поэтому у профиля может быть своя папка Claude Code:
лаунчер запускает Claude профиля с переменной `CLAUDE_CONFIG_DIR`, и вкладка Code
работает в папке `claude-config` внутри папки профиля.

- У новых профилей своя память включена; у созданных до 1.6.0 — выключена, включить её —
  на странице профиля («Своя память Claude Code»). Тогда лаунчер скопирует в папку
  профиля переписку его сессий и память проектов, которые вы отметите. В `~/.claude`
  ничего не меняется: выключите переключатель — профиль снова будет работать с общей
  памятью.
- Общими с «Основным» остаются `CLAUDE.md` (папка профиля подключает его импортом) и
  агенты, команды и навыки — лаунчер копирует их при каждом запуске профиля. Копию,
  которую изменили в профиле, он больше не трогает.
- У «Основного» всегда `~/.claude`: так его видит и Claude, открытый не из лаунчера.
- Вход во вкладку Code от папки не зависит — Claude передаёт его сам.
- Если вы сами задали `CLAUDE_CONFIG_DIR` в настройках переменных окружения Claude, она
  главнее настройки лаунчера.
- **Windows:** если Claude приходится запускать через пакет (см. «Ограничения»), передать
  переменную нельзя — профиль откроется с общей памятью.

## Где хранятся данные

| | macOS | Windows |
|---|---|---|
| Стандартная папка Claude | `~/Library/Application Support/Claude` | папка пакета MSIX (как при запуске из «Пуск») |
| Папки профилей | `~/Library/Application Support/Claude-<имя>` | `%APPDATA%\Claude-<имя>` |
| Своя папка Claude Code профиля | `…/Claude-<имя>/claude-config` | `%APPDATA%\Claude-<имя>\claude-config` |
| Профили и настройки лаунчера | `~/Library/Application Support/com.notcodeone.claudeLauncher/` | `%APPDATA%\notcodeone\ClaudeLauncher\` |

## Куда пишет лаунчер

Всё, что лаунчер создаёт или меняет на компьютере. Чужие настройки он возвращает при
выходе и по `--cleanup` (см. «Удаление»).

**Своё:**

- папка лаунчера (см. таблицу выше): `profiles.json`, `settings.json`, как были настроены
  уведомления Claude (`claude-notifications.json`), служебные файлы Kill Switch; с
  параллельными профилями — `code-session-registry.json` (только id недавних сессий Code
  и время, без названий и переписки);
- папки профилей Claude `Claude-<имя>` — их заполняет сам Claude;
- временная папка `ClaudeLauncher` в системной папке временных файлов: скачанные
  обновления Claude и журнал их установки;
- Windows: программа в `%LOCALAPPDATA%\Programs\ClaudeLauncher`, ярлыки в «Пуске», по
  желанию — на рабочем столе и в автозапуске.

**Чужое:**

- `~/.claude/settings.json` — хуки Claude Code и канал уведомлений; до первой правки
  рядом сохраняется копия `settings.json.claude-launcher-backup`;
- папки `claude-config` профилей со своей памятью: хуки в `settings.json`, импорт общего
  `CLAUDE.md`, копии общих агентов, команд и навыков (что скопировано —
  `.claude-launcher-shared.json`), а при включении своей памяти у старого профиля — копии
  переписки его сессий и выбранной памяти проектов;
- `claude_desktop_config.json` профилей — уведомления Claude и его значок
  (`menuBarEnabled`), только пока Claude этого профиля закрыт;
- с Kill Switch — `egressProxyUrl` и `disableAutoUpdates` в папках `…-3p`
  (macOS — рядом с папкой профиля, Windows — `%LOCALAPPDATA%\Claude-3p`);
- видимость значка Claude в системе: macOS — настройка строки меню Claude, Windows —
  `HKCU\Control Panel\NotifyIconSettings`;
- Windows, по включённой настройке Cowork, — правило брандмауэра `ClaudeLauncher-Cowork`;
- обновление Claude из лаунчера заменяет само приложение Claude, как его собственное
  обновление.

**Чего лаунчер не делает:** не читает пароли, токены, cookies и Связку ключей; не
отправляет никуда данные профилей; не обходит лимиты Anthropic и не переключает аккаунты
сам; не трогает вход в аккаунт в папках Claude.

## Удаление

**macOS:**

1. Выйдите из лаунчера через его меню — «Выйти из ClaudeLauncher», а не «Завершить
   принудительно». Так он вернёт Claude уведомления.
2. Уберите его настройки из Claude: хуки Claude Code в `~/.claude/settings.json`, канал
   уведомлений, значок Claude в строке меню, прокси Kill Switch:

   ```bash
   /Applications/ClaudeLauncher.app/Contents/MacOS/ClaudeLauncher --cleanup
   ```

3. Перенесите ClaudeLauncher из «Программ» в Корзину.
4. По желанию удалите папку лаунчера с профилями и настройками —
   `~/Library/Application Support/com.notcodeone.claudeLauncher` — и папки профилей
   Claude `~/Library/Application Support/Claude-<имя>` (в них вход и данные этих
   аккаунтов). Стандартную папку `Claude` не трогайте: это ваш обычный Claude.

Если лаунчер уже удалили без шага 2, поставьте его снова, выполните `--cleanup` и удалите.

**Windows:** «Параметры» → «Приложения» → ClaudeLauncher → «Удалить». Хуки, значок и
уведомления Claude удаление вернёт само, как и правило брандмауэра для Cowork, если оно
стоит (Windows спросит разрешение администратора). Профили Claude и их данные удаление не трогает —
папки `%APPDATA%\Claude-<имя>` и `%APPDATA%\notcodeone\ClaudeLauncher` можно удалить
вручную.

## Ограничения

- `--user-data-dir` — неофициальный способ; обновление Claude может его сломать.
- Переключение закрывает Claude — работа, которая в нём идёт, прервётся.
- **Windows:** при закрытии окна Claude уходит в трей, а не выходит. Поэтому лаунчер
  просит его выйти так же, как Windows при выходе из сеанса, — и только когда Claude
  закончил загрузку (иначе он завершится без своей уборки). Если Claude так и не вышел,
  лаунчер предложит закрыть его принудительно.
- **Windows:** на части компьютеров система не даёт запускать Claude из папки его пакета
  напрямую. Тогда лаунчер запускает профиль через пакет, как из «Пуска», и новые файлы
  профиля Windows может хранить в папке пакета: `%LOCALAPPDATA%\Packages\Claude_…\LocalCache\Roaming`.
- Приложение Claude читает настройки уведомлений только при запуске (см. «Уведомления»).

## Разработка

Flutter 3.44, Dart 3.12. Сборка для macOS — в Xcode 26 или новее: значок приложения
(`macos/Runner/AppIcon.icon`) — в формате Icon Composer.

```bash
flutter run -d macos          # или -d windows
flutter analyze
flutter test                  # юнит-тесты
flutter test integration_test/macos_host_test.dart -d macos   # на настоящем Claude
python3 tool/generate_icons.py   # перегенерировать все значки (macOS, нужен Pillow)
```

Интеграционный тест запускает отдельный тестовый профиль Claude во временной папке,
находит его, закрывает и удаляет папку. Уже открытый Claude не трогается.

Структура:

- `lib/src/claude/` — всё, что зависит от ОС: поиск Claude, список процессов, запуск, закрытие.
- `lib/src/launcher_controller.dart` — профили и логика переключения.
- `lib/src/integrations/` — события Claude Code, сессии на карточке и уведомления вместо
  самих Claude (`notification_handoff.dart`).
- `lib/src/location/` — проверка страны; список стран — `countries.dart`.
- `lib/src/updates/` — проверка и установка обновлений; `tool/install.sh` и
  `tool/install.ps1` — установка одной командой.
- `lib/src/tray.dart`, `lib/src/ui/` — меню в трее и окно лаунчера.
- `macos/Runner/MainFlutterWindow.swift` — закрытие и активация конкретного экземпляра
  Claude, окно лаунчера поверх остальных.

### Как устроено изнутри

- **Уведомления.** Как было до лаунчера, записано в `claude-notifications.json` рядом с
  профилями. После выхода в фоне остаётся наблюдатель — тот же ClaudeLauncher с флагом
  `--return-claude-notifications`, без окна и значка: он возвращает настройки открытым
  Claude, когда их закроют, и завершается. На macOS закрытия ждёт `/bin/sh`, а наблюдатель
  запускается только на возврат настроек — так Finder может заменить приложение новой
  версией. Если лаунчер завершился аварийно, уведомления вернутся при следующем выходе.
- **Сессии.** Название сессии берётся из её переписки, а открывается она по ссылке
  `claude://claude.ai/epitaxy/<id>`, которую выдаёт само приложение Claude (id сессии хук
  передаёт в заголовке). Если лаунчер перезапустили посреди задачи, её начало он находит
  в переписке.
- **Проверка страны.** Лаунчер спрашивает первый сервис, следующий — если предыдущие не
  ответили за 300 мс или ответили ошибкой. Ответ младше 30 секунд переиспользуется. Без
  сети профиль по умолчанию ждёт около 20 секунд. Украина в списке Anthropic есть, кроме
  нескольких областей, а по IP область не различить, так что лаунчер решает по стране.
- **Окно поверх Claude.** Пока профиль по умолчанию открывается, и ещё 20 секунд после,
  лаунчер раз в 250 мс проверяет, активно ли его окно. Если нет, а пользователь последнюю
  секунду ничего не нажимал, окно возвращается вперёд. На macOS время с последнего клика
  или клавиши — `CGEventSource`, на Windows — `GetLastInputInfo`, там в счёт идёт и
  движение мыши.

### Установщики

Собрать локально (после `flutter build …`):

```bash
tool/make_dmg.sh 1.4.1                                         # macOS
iscc /DAppVersion=1.4.1 windows\installer\claude_launcher.iss  # Windows, Inno Setup 6
```

Окно DMG (фон, размер, положение значков) берётся из шаблона `tool/dmg/template.dmg`.
`make_dmg.sh` только кладёт в него приложение, поэтому Finder для сборки не нужен, и она
работает в CI. Фон в macOS 26 должен задать сам Finder: записи `dmgbuild`, AppleScript и
ссылку на скрытый файл он не показывает. Поэтому шаблон готовится отдельно, с одним
ручным шагом в Finder:

```bash
python3 tool/generate_dmg_background.py   # фон: tool/dmg/background.tiff (нужен Pillow)
tool/make_dmg_template.sh                 # шаблон: tool/dmg/template.dmg
```

Сборки каждого коммита собирает GitHub Actions: вкладка **Actions** → запуск **Build** →
артефакты.

### Версии

Номер версии — в `pubspec.yaml`: MAJOR.MINOR.PATCH и номер сборки после `+`. Из него
берутся версия приложения в macOS и Windows, имена установщиков и номер в подвале окна.
Что изменилось в каждой версии — в [CHANGELOG.md](CHANGELOG.md).

Как выпустить версию:

1. Поднять номер в `pubspec.yaml`: для исправлений — PATCH, для нового — MINOR, для
   несовместимых изменений — MAJOR. Номер сборки каждый раз увеличивать на 1.
2. Добавить в `CHANGELOG.md` раздел `## X.Y.Z — дата` с тем, что изменилось.
3. Закоммитить, поставить тег и запушить его: `git tag vX.Y.Z && git push origin main vX.Y.Z`.

По тегу GitHub Actions собирает установщики и публикует выпуск «ClaudeLauncher X.Y.Z» с
текстом из раздела версии в `CHANGELOG.md` (`tool/release_notes.sh`). Если тег не
совпадает с версией в `pubspec.yaml` или раздела нет, выпуск не публикуется.
